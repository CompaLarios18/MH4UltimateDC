# N1 · Headless runtime: the game boots without Azahar

The native runtime's first phase: loader, guest memory, the code-library host, kernel objects, the scheduler, the SVCs, IPC and the services, all headless (no window, no sound), driven by the runner's scripts and checked against N0's oracles. The phase's exit is in [`../ROADMAP.md`](../ROADMAP.md#5-phases); the workflow is [`../AGENTS.md`](../AGENTS.md).

## Rules for code in `native/`

These add to the worker rules of [`../AGENTS.md`](../AGENTS.md#8-rules-for-workers) and to the shared rules at the top of [`N0.md`](N0.md) (Old 3DS reference runs, no buffer contents in output, *(CI)* items, needs tags). They apply to `native/` in every phase.
- **Language and layout:** C++20 with clang (D18), namespace `mh4n`.
  - Each module is a static library in its own directory under `native/src/`, at any depth, with its own `CMakeLists.txt`: `native/src/kernel/` is `mh4n_kernel`, `native/src/services/fs/` is `mh4n_services_fs`. A module names the modules it uses with `mh4n_module(SOURCES … DEPENDS …)`, never with `target_link_libraries` (CMake refuses a library linked both whole and normally); third-party libraries link normally. Programs live in `native/runner/` and `native/tools/<name>/`, which hold only `main` and its glue: a tool's logic is a module, so tests can link it. Tests are `native/tests/<name>_test.cpp`, one doctest binary each, linked against every module.
  - **Nothing shared needs editing to add something.** CMake finds new modules, tools and tests by themselves (N1-01). Options, services, GPUs, input sources, audio sinks, boot steps and capture-player checks register themselves from their own module through `mh4n/registry.h` (N1-01); every module is linked whole, so a registration nobody references still runs. A WP adds its piece in its own directory.
  - Public headers live in `native/include/mh4n/`. Once merged they are contracts: only the orchestrator changes them, and a WP that needs a change proposes it in its report.
  - Our own headers are included as `mh4n/<name>.h`, or relative to the including file.
- **One configure line**, everywhere (workers, reviewers, the orchestrator, CI on Linux):
  ```
  cmake -S native -B build/native -G Ninja -DCMAKE_C_COMPILER=clang -DCMAKE_CXX_COMPILER=clang++ \
        -DCMAKE_BUILD_TYPE=RelWithDebInfo -DMH4N_WERROR=ON
  cmake --build build/native
  ctest --test-dir build/native --output-on-failure
  ```
  `MH4N_REQUIRE_TEST_DATA=1 ctest …` turns a test that needs the built ARM programs (`cpu_test`) from a skip into a failure when Python 3, clang, ld.lld, llvm-objcopy or llvm-readelf is missing (and always on Windows, where they are not built); CI (Linux) sets it. The first build of a session takes minutes: start it in the background and poll (AGENTS §7). Once a WP needs SDL3 (N2b), `source ~/.mh4n_env &&` comes first.
- **No Azahar module, header or library.** `tools/native/check_native_deps.py` (N1-01) enforces it in CI.
- **Azahar is the reference for behaviour:** result codes, edge cases, structure layouts, default values, the order things happen in. The game runs on it, so where 3dbrew and Azahar disagree, follow Azahar and say so in a comment.
  - Copying a function or a table from it is allowed (D6), with the provenance header of AGENTS §8 rule 6.
  - The architecture is ours: flat memory, fibers under our scheduler, the game clock, services that run on the calling guest thread (D22).
- **Logging** goes through `MH4N_LOG`; no `printf` outside the runner.
- **Threads (principle 6):** only the scheduler's host thread touches guest memory and kernel objects. The exception is a buffer that a request in progress lent to a service. Other host threads hand work over with `Kernel::Post`.
- **Services** implement the commands `docs/research/service-commands.md` (N0-23) lists for them, with Azahar's behaviour. **Unknown commands never crash:** anything else the game sends is logged once as `unimplemented <service> <header>` and answered the way Azahar answers it.
- **Exit statuses of the native runner**, as `mh4u_runner`'s: 0 when the program exits or a `--ms`/`--frames` limit is reached; 2 when loading fails (a missing file, a code library that doesn't match); 3 on a runtime error (a bad memory access, svcBreak, a fatal error through `err:f`); 4 when the recompiled code stops (code that wasn't recompiled, a bad return, a trap).
- **Time in comparisons:** the reference charges emulated time, the native runtime uses the host's. Golden checks compare scenes within ±2 frames and the `eq` values of `observable.txt` (N0-07); file requests answer after Azahar's modelled delay by default (D26), so loads take as many frames as in the reference.
- **Commands whose replies depend on time** (a tick count, a timer state) differ between runtimes. Put the ones you find in a file under `build/` for your check (`mh4n_ipc_replay --time-dependent`, `compare_ipc_traces.py --ignore`), and propose them for `config/native/ipc_time_dependent.txt`, each with a one-line reason, in `proposed-shared-changes`. Only the orchestrator edits that file.
- **Vulkan is loaded at run time** (volk, vendored with the backend in N2-21), since every binary links every module: a binary starts on a machine without a Vulkan driver, and tests that need a device skip with a message when there is none (they find lavapipe in the cloud and in Linux CI).

**Oracles in this phase:**
- `port/tests/conf_*.c`: our own 3DS test programs (N1-08), with Azahar's output committed as the expected output. No game data, so they also run in public CI.
- The golden sessions (N0-09 to N0-11), through `golden.py check --candidate-runner` and the IPC replay harness (N1-11). They need the dump. A *(with the dump)* item that uses a golden session's recordings (`build/golden/<S>/…`) runs once the WP that records it is done (N0-09: G1, G2, G6; N0-10: G3, G4, G7, G3-perf; N0-11: G5); until then it stays `dump-check pending`, and the WP can be reviewed and merged on its other checks.

### N1-01 · `native/` skeleton, build and CI
- **Size / agent:** M · native-worker-high
- **Depends on:** N0-02, N0-03 · **Needs:** ci
- **Goal:** the `native/` tree builds with CMake and clang and runs unit tests through CTest; new modules, tools, tests and registrations are picked up without editing a shared file; CI builds and tests it on every push and PR; a CI check proves nothing in it uses Azahar.
- **Read first:** [`../DECISIONS.md`](../DECISIONS.md) (D3, D6, D18, D20); [`../ROADMAP.md`](../ROADMAP.md) §3; `port/CMakeLists.txt` (style); `.github/workflows/native.yml` and `docs/native/CI.md` (N0-03); `port/tests/build_svc_test.py` (what building the ARM test programs needs).
- **Files (allowlist):** `native/**` (new), `tools/native/check_native_deps.py` (new), `tests/test_native_check_native_deps.py` (new), `tests/test_native_cmake_layout.py` (new), `.github/workflows/native.yml` (a `native` job).
- **Spec:**
  - **Layout:**
    ```
    native/CMakeLists.txt            project, options, include directories, the module, tool and test discovery
    native/THIRD_PARTY.md            vendored code and copied Azahar pieces, one row each
    native/third_party/doctest/      doctest 2.4.11, single header, with its LICENSE
    native/third_party/fmt/          fmt 11.x, with its LICENSE
    native/include/mh4n/             public headers (contracts)
    native/src/common/               mh4n_common
    native/runner/                   mh4u_native_runner
    native/tools/                    one directory per tool, each with its CMakeLists.txt
    native/tests/                    <name>_test.cpp
    ```
  - **CMake:** 3.25 or later, `project(mh4n C CXX)`, C++20, `-Wall -Wextra`. Options: `MH4N_TESTS` (ON), `MH4N_WERROR` (OFF; CI and the configure line set it), `MH4N_ASAN` (OFF), `MH4N_DEBUG_GUARD` (OFF; N1-02).
    - **Modules:** every directory under `native/src/` (at any depth) that has a `CMakeLists.txt` is added, and names its library `mh4n_<path with '_' for '/'>` through a helper, `mh4n_module(SOURCES … [DEPENDS <modules>] [THIRD_PARTY <targets>])`. The helper links the modules in `DEPENDS` (and `mh4n_common`, always) through the `WHOLE_ARCHIVE` feature (`$<LINK_LIBRARY:WHOLE_ARCHIVE,…>`), and third-party targets normally. The interface target `mh4n::all` links every module the same way, so static registrations survive the linker and no library is ever linked both whole and normally.
    - **As built:** `DEPENDS` takes full library names (`mh4n_services_fs`), not paths. A tool's `CMakeLists.txt` calls `mh4n_program(<exe> SOURCES …)`. A test file opts out of the shared `main` with a line `#define MH4N_TEST_OWN_MAIN` (CMake detects the line in the file).
    - **Tools:** every `native/tools/*/` with a `CMakeLists.txt` is added.
    - **Tests:** one doctest binary per `native/tests/*_test.cpp`, linked against `mh4n::all`, registered with CTest. A test file that defines `MH4N_TEST_OWN_MAIN` before including doctest supplies its own `main` (for subprocess tests such as N1-02's fault test).
  - **`mh4n_common`** (headers `mh4n/types.h`, `mh4n/log.h`, `mh4n/assert.h`, `mh4n/crc32.h`, `mh4n/registry.h`, `mh4n/options.h`):
    - `types.h`: `u8` … `s64`; `Result` (`u32`); `MakeResult(description, module, summary, level)` with the 3DS bit layout (description bits 0–9, module 10–17, summary 21–26, level 27–31); `IsError(Result)`;
    - `log.h`: `MH4N_LOG(level, "Category", fmt, args…)` with fmt; levels Trace to Critical; a filter parsed from the syntax of `mh4u_runner --log` (`"*:Info Kernel:Debug"`);
    - `assert.h`: `MH4N_ASSERT(cond, fmt, …)` and `MH4N_UNREACHABLE()`, which log and abort;
    - `crc32.h`: the standard reflected CRC-32 (the code library's `text_crc32` uses it);
    - `registry.h`: `Registry<T>` (one per type `T`: `Add(name, value)`, `Find(name)`, `All()` in name order, duplicate names an error at start-up) and `MH4N_REGISTER(T, "name", value)`, which registers from a static object in the module that uses it;
    - `options.h`: `MH4N_OPTION(scope, "--name", "ARG", "help")` (empty ARG for a flag; `scope` is any string naming the program: `runner`, `capture-player`, `ipc-replay`, a tool's name); `Options ParseOptions(scope, argc, argv)` with positional arguments, `Has`, `Get` (the last value), `All` (every value of a repeatable option) and typed getters; an unknown option is an error that prints the usage; `Usage(scope)` lists the registered options of that scope in name order.
  - **`mh4n/gpu.h`**, the GPU contract (D20; header only, implemented by the null GPU in N1-17, the capture player's GPUs in N2-02 and the renderer in N2). It mirrors the entry points of Azahar's `VideoCore::GPU`, which N0-05's captures record:
    ```cpp
    namespace mh4n::gpu {
    struct GxCommand { u32 words[8]; };          // as in GSP shared memory; id in the low byte of word 0
    struct FrameBufferInfo { u32 active_fb, address_left, address_right, stride, format, shown_fb, unknown; };
    enum class Interrupt : u32 { PSC0 = 0, PSC1 = 1, PDC0 = 2, PDC1 = 3, PPF = 4, P3D = 5, DMA = 6 };

    class Host {   // what a GPU needs from the runtime
    public:
        virtual ~Host() = default;
        virtual u8* PhysicalPointer(u32 paddr, u32 size) = 0;      // FCRAM, VRAM or DSP RAM, else nullptr (see below)
        virtual std::optional<u32> VirtualToPhysical(u32 vaddr) = 0;
        virtual void SignalInterrupt(Interrupt id, u64 delay_ns) = 0; // thread-safe; goes through Kernel::Post
        virtual void Post(std::function<void()> work) = 0;            // thread-safe; runs on the scheduler thread
                                                                       // at a safe point (a capture's host: at once)
    };

    class Gpu {
    public:
        virtual ~Gpu() = default;
        virtual void Execute(const GxCommand& command) = 0;     // virtual addresses, as the game wrote them
        virtual void WriteReg(u32 addr, u32 value) = 0;          // GSP WriteHWRegs: 0x1EB00000 + register offset
        virtual u32 ReadReg(u32 addr) = 0;
        virtual void SetBufferSwap(u32 screen, const FrameBufferInfo& info) = 0;
        virtual void SetColorFill(u32 fill) = 0;                 // the raw ColorFill register word, both screens
        virtual void FlushRegion(u32 vaddr, u32 size) = 0;       // the CPU wrote this range (FlushDataCache)
        virtual void InvalidateRegion(u32 vaddr, u32 size) = 0;  // the CPU is about to read this range
        virtual void VBlank(u32 screen) = 0;                     // a refresh of `screen` finished
    };

    using GpuFactory = std::function<std::unique_ptr<Gpu>(Host&, const Options&)>;   // by name: MH4N_REGISTER(gpu::GpuFactory, …)
    }
    ```
  - **`mh4u_native_runner`:** `--help` prints the usage (`Usage("runner")`) and `--version` the git revision; N1-09 fills it in.
  - **Unit tests:** `native/tests/common_test.cpp` (log filter parsing, the `MakeResult` layout, CRC-32 test vectors), `registry_test.cpp` and `options_test.cpp`.
  - **`tools/native/check_native_deps.py`** exits 1, listing each offence, if:
    - a file under `native/` includes a path starting with `core/`, `video_core/`, `audio_core/`, `common/`, `network/`, `input_common/`, `web_service/` or `citra`;
    - a `CMakeLists.txt` under `native/` names an Azahar target (`citra_common`, `citra_core`, `video_core`, `audio_core`, `network`, `input_common`, `web_service`) or a path under `port/azahar/`.

    Files from `port/src/` that `native/` compiles or includes (`fiber.cpp`, `fiber.h`, `schedule.cpp`, `schedule.h`, `hooks.cpp`, `hooks.h`, `platform.h`) are checked with the same rules.
  - **CI:** a `native` job in `native.yml` on `ubuntu-24.04`, on pushes and PRs: install clang, lld, llvm (for `llvm-objcopy` and `llvm-readelf`), cmake, ninja, Python 3 with `pip install -r requirements.txt` (building the ARM test programs uses `tools/difftest.py`), and `libvulkan-dev mesa-vulkan-drivers glslang-tools spirv-tools`; configure with the line above; build; ctest; run `check_native_deps.py`.
- **Done when:**
  - the configure line, the build and ctest succeed in the cloud;
  - `python3 -m pytest tests/test_native_check_native_deps.py` passes (synthetic trees: clean, an Azahar include, an Azahar target);
  - `python3 -m pytest tests/test_native_cmake_layout.py` passes (skipped without cmake and clang): it copies `native/` into a temporary directory, adds a module two levels down (`native/src/x/y/` in the copy), a module that depends on another and on `mh4n_common`, a registration in a module nothing references, a tool and a test with its own `main`, then configures with the configure line, builds, runs ctest and the tool, and checks the registration is found at run time;
  - *(CI)* the `native` job is green.
- **Traps:** pin the vendored versions in `THIRD_PARTY.md`, and vendor only the files the build needs.
- **Out of scope:** any runtime module.

### N1-02 · Guest memory
- **Size / agent:** M · native-worker-high
- **Depends on:** N1-01 · **Needs:** none
- **Goal:** the guest's 4 GiB address space as one host reservation (principle 2), with mapping bookkeeping, the physical view the GPU and DSP use, Azahar's FCRAM allocation order, and clear reports of bad accesses.
- **Read first:**
  - [`../ROADMAP.md`](../ROADMAP.md) §3, principle 2; `tools/recomp/runtime/recomp.h` (flat mode: guest address A lives at `ctx->mem + A`);
  - in Azahar: `src/core/memory.h` (the virtual and physical address constants), `src/core/hle/kernel/memory.cpp` (`MemoryRegionInfo`; the region sizes per memory mode), `src/core/hle/kernel/vm_manager.h` (memory states and permissions);
  - 3dbrew *Memory layout*.
- **Files (allowlist):** `native/include/mh4n/memory.h`, `native/src/memory/**`, `native/tests/memory_test.cpp`, `config/native/zero_regions.txt` (new).
- **Spec:**
  - **Reservation:** `GuestMemory::Create()` reserves 4 GiB plus a 64 KiB guard of host address space, inaccessible (POSIX `mmap` with `PROT_NONE` and `MAP_NORESERVE`; Windows `VirtualAlloc(MEM_RESERVE)`). `Base()` is what goes in `RCtx::mem`.
  - **Mapping:** `Map(vaddr, size, perm, state)`, `Unmap`, `Protect`, `Query(vaddr)` (base, size, permission and state of the block containing vaddr, for svcQueryMemory) and `IsMapped(vaddr, size)`.
    - Mapped host pages are readable, writable and zero-filled. Guest permissions are kept for `Query` but not enforced: recompiled code never executes guest memory, and Apple silicon's host pages (16 KiB) are coarser than the guest's (4 KiB).
    - Unmapping gives the pages back to the OS (decommit, or `madvise(MADV_DONTNEED)` and `PROT_NONE`).
    - Blocks merge and split as in Azahar's VMA list, so `Query` returns the same extents. States and permissions use the 3DS values.
  - **Fixed regions** mapped at creation: VRAM at `0x1F000000` (6 MiB) and DSP RAM at `0x1FF00000` (512 KiB). The loader maps the config memory and the shared page (N1-03).
  - **Zero regions:** `config/native/zero_regions.txt` (format `<start> <end>  # reason`) starts with `0x00000000 0x000fffff  # reads of address 0 (the quest-loading race); Azahar returns 0`. The build embeds it (CMake generates a header from the file at configure time). The policy is a parameter of `GuestMemory::Create` (default from `MH4N_DEBUG_GUARD`): mapped read-write and zero-filled (release), or left unmapped, so the access faults (guard).
  - **Physical view:**
    - `PhysicalPointer(paddr, size)`: non-null only when the whole range `[paddr, paddr + size)` lies inside one area and is mapped; a range that leaves its area, or is partly unmapped, gives null, and size 0 is the single byte at `paddr` (so an area's end address is null here). `gpu::Host::PhysicalPointer` is stricter at one point: it must accept the address one past the end of an area for size 0 (`gpu.h`; the GX engine, N2-03, cuts DMA, fills and transfers by searching the longest valid prefix, and `CaptureHost` does this), so the runtime's `Host` (N1-09) adds that rule on top of `GuestMemory`. The areas: FCRAM `0x20000000`–`0x28000000` through the linear heap (vaddr = paddr − `0x20000000` + the linear heap base; null where that isn't mapped), VRAM `0x18000000`–`0x18600000` (at `0x1F000000`), DSP RAM `0x1FF00000`–`0x1FF80000`;
    - `VirtualToPhysical(vaddr)` for the same three areas.
  - **FCRAM allocator** (`FcramRegions`, bookkeeping only):
    - the APPLICATION, SYSTEM and BASE regions in that order from FCRAM offset 0, with the sizes of Azahar's table for the memory mode (mode 0, Prod: 64, 44 and 20 MiB; mode 2, Dev1: 96, 12 and 20 MiB);
    - `HeapAllocate(size)` takes free space from the top of the region, possibly in several pieces; `LinearAllocate(size)` takes the first fit from the bottom; `LinearAllocate(offset, size)` a given range; `Free(offset, size)`;
    - the same results as Azahar's `MemoryRegionInfo` for the same calls. Azahar uses `boost::icl`; use a `std::map` of free intervals.
  - **Bad accesses:** an access to an unmapped page inside the reservation writes one line to stderr (the guest address, read or write when the platform says, the current guest thread id and its LR) and ends the process with `_exit(3)`. The current guest context comes from a thread-local `RCtx*` that the code host sets (N1-04). POSIX: a `SIGSEGV`/`SIGBUS` handler on `sigaltstack`; Windows: a vectored exception handler. Faults outside the reservation go to the previous handler.
  - **Helpers:** `Read<T>`, `Write<T>`, `ReadBlock`, `WriteBlock`, `ReadString(vaddr, max)`. They check the range is mapped and return an error instead of faulting.
- **Done when:**
  - ctest passes, with cases for:
    - map, unmap, protect and query, including merging and splitting blocks;
    - zero regions under both policies;
    - `PhysicalPointer` and `VirtualToPhysical` for each area;
    - the allocator against a sequence worked out by hand from Azahar's algorithm (heap pieces from the top, linear first fit from the bottom, frees in between), for both memory modes;
    - a bad access, run as a subprocess (`memory_test --fault-test`, a test with its own `main`), printing the guest address and exiting with status 3;
  - the code compiles on Linux. The Windows and macOS paths are written now and tested in N1-22.
- **Traps:** the signal handler must be async-signal-safe: `write(2)` and `_exit` only, no fmt, no allocation. Don't commit the reservation up front.
- **As built (N1-02), for the WPs that use it** (the contract is `native/include/mh4n/memory.h`):
  - `GuestMemory::Create` takes `GuestMemoryOptions {zero_policy, zero_regions, host_page_size}`. `Map` has an optional `backing` token: pass the FCRAM physical address of the piece (`kFcramPaddr + offset`) so `Query` returns Azahar's block extents (adjacent blocks merge only when their backings are contiguous or both absent). `ChangeState` is for the aliasing states of Map/Unmap (N1-05 shared memory, N1-07 ControlMemory). `Read`/`Write` return `std::optional`/`bool`; `VirtualToPhysical` gives `nullopt` for address 0 and unknown addresses.
  - N1-03: `SetLinearHeapArea(base)` takes the linear heap's base (`0x14000000` for a kernel version below `0x22C`, else `0x30000000`); call it before the GPU asks for `PhysicalPointer`.
  - N1-04: the code host calls `mh4n::SetFaultContext(ctx, thread_id)` on every switch into a guest fiber and `ClearFaultContext()` on the way out, and each host thread that runs guest code calls `GuestMemory::PrepareThreadForFaults()` once.
- **Out of scope:**
  - ControlMemory and the other SVCs (N1-07);
  - one physical page at two guest addresses (host aliasing): unsupported. If the kernel census (N0-12) shows the game needs it, the WP that meets it stops with `needs-decision`.

### N1-03 · Loader and system pages
- **Size / agent:** M · native-worker
- **Depends on:** N1-02 · **Needs:** dump-check
- **Goal:** the runtime sets up the game's process as Azahar does in Old 3DS mode (code segments, stack, main-thread parameters, memory mode, linear heap base, config memory, shared page), from a game folder or from an ELF test program. `tools/native/prepare_game.py` makes the game folder from the player's dump.
- **Read first:**
  - `tools/exheader.py`, `tools/extract_ncch.py`, `tools/blz.py`; `tests/test_extract_ncch.py` (its `make_cia` helper builds synthetic CIAs) and `tools/make_cxi.py`;
  - in Azahar:
    - `src/core/loader/ncch.cpp` (`LoadExec`: the process from the exheader; the memory mode from the ARM11 local capabilities' system mode, near line 80);
    - `src/core/loader/elf.cpp` and `src/core/loader/loader.h` (ELF programs: `Set3dsxKernelCaps`, memory mode Dev1 by default, `ApplyAppMaxCPUSetting(process, 1, 89)`, main-thread priority 48, stack `DEFAULT_STACK_SIZE` = 0x4000);
    - `src/core/hle/kernel/process.cpp` (`ParseKernelCaps`; `Run`, which maps each segment and then the stack; `GetLinearHeapAreaAddress`: kernel version below 0x22C gives `0x14000000`, otherwise `0x30000000`);
    - `src/core/hle/kernel/config_mem.cpp`/`.h`, `shared_page.cpp`/`.h` (`init_time` and how the date advances), and `src/core/hle/kernel/memory.cpp` (`MemoryInit`: what config memory reports about memory);
  - `port/src/runner.cpp` near line 980 (the fixed start date of reference runs);
  - 3dbrew *NCCH/Extended Header*.
- **Files (allowlist):** `native/include/mh4n/loader.h`, `native/src/loader/**`, `native/tests/loader_test.cpp`, `native/runner/**` (`--print-process`), `tools/native/prepare_game.py` (new), `tests/test_native_prepare_game.py` (new), `tools/exheader.py` (parse the ARM11 local and kernel capabilities too), `tests/test_exheader.py` (new).
- **Spec:**
  - **Game folder**, written by `prepare_game.py --base GAME --update UPDATE.cia [-o DIR]` (GAME is a `.3ds`, `.cci` or `.cxi`; DIR defaults to `build/native-game`, since `build/game` is `build_game.py`'s):
    ```
    exheader.bin       the update's exheader
    code.bin           the update's code, decompressed
    romfs.bin          the base game's RomFS section
    update_romfs.bin   the update's RomFS section
    info.txt           titles, versions, sizes, CRC-32 of code.bin
    ```
    It uses `extract_ncch.py` (with `--romfs`) for both inputs, decompresses with `blz.py` when the exheader says so, and refuses an update other than v1.3.0 (`config/versions.json`). RomFS copies are streamed.
  - **`tools/exheader.py`** also parses the ARM11 local capabilities (main-thread priority, ideal processor, system mode, resource-limit category, schedule mode, maximum CPU) and the kernel capabilities (kernel version, memory region, handle-table size).
  - **Loader, game folder** (C++, reading `exheader.bin` itself):
    - the memory mode from the system mode, as Azahar's NCCH loader with New 3DS mode off;
    - maps text (RX), ro (R) and data plus bss (RW, bss zeroed) at their addresses, then the stack at `[0x10000000 − stack size, 0x10000000)`, in Azahar's order and with `FcramRegions::HeapAllocate` for each, so later linear allocations land where they do in Azahar;
    - picks the linear heap base from the kernel version;
    - returns a `ProcessImage`: entry (the text start), stack top `0x10000000`, main-thread priority, ideal processor, memory mode, kernel version, program id, the main thread's FPSCR `0x03C00010`, the resource-limit category, and the schedule mode and maximum CPU that Azahar's NCCH loader passes to `ApplyAppMaxCPUSetting` (`src/core/loader/ncch.cpp` near line 180). The kernel creates the thread and applies the CPU setting from it (N1-27).
  - **Loader, ELF** (test programs): maps the `PT_LOAD` segments at their addresses with Azahar's ELF defaults: kernel version `0x23A`, memory mode Dev1, priority 48, stack 0x4000, the address mappings of `Set3dsxKernelCaps`, and the core-1 CPU setting (1, 89), recorded in the `ProcessImage` for N1-27.
  - **Config memory** at `0x1FF80000` (read-only): the values of Azahar's `ConfigMem::Handler` (firmware 11.17.0), plus the app memory type and size as Azahar sets them for the memory mode.

### N1-04 · Code host and guest fibers
- **Size / agent:** M · native-worker-high
- **Depends on:** N1-02, N1-03, N0-17 · **Needs:** none
- **Goal:** load a code library built with `--native`, check that it was made from the loaded code, run guest code on fibers with the right floating-point state, and route every runtime callback of `recomp.h`.
- **Read first:** `tools/recomp/runtime/recomp.h` (all of it: `RCtx`, `RHost` v5, `RCodeInfo`, `rc_build_mode`); `tools/recomp/runtime/rc_dll.c`; `port/src/arm_recomp.cpp` (how the Azahar backend does each of these: the CRC check, `RHost`, `Call`, `GuestMain` with `rc_apply_rounding`, `Svc`, `Budget`, `Fail`); `port/src/fiber.h`/`.cpp`; [`../../RECOMPILER.md`](../../RECOMPILER.md).
- **Files (allowlist):** `native/include/mh4n/cpu.h`, `native/src/cpu/**` (its `CMakeLists.txt` compiles `port/src/fiber.cpp` into the module), `native/tests/cpu_test.cpp`, `port/tests/codehost_test.c` (new).
- **Spec:**
  - **`CodeLibrary::Load(path)`** with `dlopen` or `LoadLibraryW` (UTF-8 path converted), then `rc_code_init` with `RHost{5, sizeof(RCtx), call, svc, trap, bad_return, budget, slow_read, slow_write, preempt_flag}`. Errors are messages a player can act on: not a code library; built against a different `recomp.h`; built for Azahar (`rc_build_mode` 0: "rebuild with --native"); a deterministic build without `--deterministic`, and the reverse.
  - **`Matches(text)`:** the CRC-32 of the loaded text segment equals `text_crc32` (and the sizes agree). If not, the runtime refuses to start (exit status 2, D13).
  - **Missing functions:** the library resolves its own targets, so the host's `call` callback only sees targets that aren't in it. It calls the fallback set with `SetMissingFunctionHandler` (the interpreter, N1-28), or fails (exit status 4) with `not recompiled: <addr> (lr <addr>); add it to config/extra_entries.txt and rebuild`.
  - **`GuestThread`** owns an `RCtx` (zeroed; `mem = Base()`, `cpsr_misc = 0x10`, `user` = the thread) and a fiber (`Port::Fiber`, 8 MiB stack like the Azahar backend's). The fiber's entry applies `rc_apply_rounding(fpscr)` and calls the guest entry. Returning from the entry is a failure: threads end with svcExitThread.
  - **Current context:** a thread-local `RCtx*` (for the fault handler of N1-02 and for logs), set on every switch into a guest fiber.
  - **Callbacks:**
    - `svc` → the kernel's SVC dispatcher, through an interface the kernel sets (N1-07);
    - `budget` → the scheduler's `Preempt()` (N1-06);
    - `trap` and `bad_return` → fail (exit status 4), logging r0–r15, the CPSR and the function;
    - `slow_read` and `slow_write` → fail ("a flat-memory library was expected").
  - **`preempt_flag`** belongs to the scheduler (one per host thread); the code host passes its address.
  - **Floating point:** after every switch back into a guest fiber, and after every SVC, re-apply `rc_apply_rounding(ctx->fpscr)`, as the Azahar backend does.
  - **Test program** `port/tests/codehost_test.c` (freestanding, our own code): computes a CRC-32, a VFP dot product and a Thumb call through a function pointer, prints each with OutputDebugString and calls ExitProcess. The module's CMake builds it and its `--native` code library at build time (`port/tests/build_svc_test.py` and `recomp.build`), and the test loads it with the loader (N1-03) into guest memory (N1-02).
- **Done when:** ctest passes:
  - the test program runs through the code host with a fake SVC handler (OutputDebugString and ExitProcess only) and prints the values the host computes in C++;
  - two guest threads with different FPSCR rounding modes keep their own modes across switches;
  - a library whose CRC doesn't match is refused with the message;
  - a call to a missing function produces the message.
- **Traps:**
  - Fiber switches through `ucontext` cost a system call each; count them (N1-06) before optimising anything.
  - On Windows, load the library with `LoadLibraryExW(..., LOAD_WITH_ALTERED_SEARCH_PATH)`.
- **As built (N1-04), for N1-06, N1-07, N1-27 and N1-28** (the contract is `native/include/mh4n/cpu.h`):
  - `CodeLibrary::Load(path, deterministic, preempt_flag, &error)` takes the scheduler's preemption flag and the `--deterministic` setting; `Matches(text, text_base, &error)` also compares the text base (stricter than the spec's wording) and its message names both CRCs. `CodeHost` owns the library (`SetLibrary`) and routes the callbacks: `SetSvcHandler(void(RCtx&, imm, next_pc))` (the dispatcher writes r15 itself), `SetBudgetHandler(void(RCtx&))` (N1-06's `Preempt`; it clears the flag), `SetMissingFunctionHandler(void(RCtx&, target))` (N1-28).
  - `CodeHost::NewThread(id, optional C++ Entry)` starts the guest function at `Context().r[15]` (bit 0 means Thumb), so N1-27 sets the registers after creating the thread. `Enter(t)` runs a thread from the host stack and returns when any guest thread calls `Yield()` or fails; `SwitchTo(u)` switches guest to guest directly. Both set the thread-local current `RCtx` and call `SetFaultContext` / `ClearFaultContext` (N1-02). A failure is recorded once in `CodeHost::Failure()` (message and register dump) and the runtime ends with exit status 4; a thread is never resumed after a failure.
  - A fiber is freed without unwinding: svcExitThread (N1-07) must not hold a `shared_ptr` or any other owner on the thread's stack at its last switch, and a `GuestThread` is destroyed only when it is not the running one.
  - Floating point: the host default (FPSCR 0) is applied around every handler and after `Enter` returns; the guest's FPSCR is applied again after every handler and after every switch back into a guest fiber. On Linux `swapcontext` keeps MXCSR per context, so no test can see the re-apply after a switch: the Windows and macOS paths depend on it (N1-22).
  - Not tested: the "built against a different recomp.h" message and the deterministic budget refills (N1-25).
- **Out of scope:** the scheduler (N1-06); the interpreter (N1-24, N1-28).

### N1-05 · Kernel objects and handle table
- **Size / agent:** M · native-worker-high
- **Depends on:** N1-02 · **Needs:** none
- **Goal:** the kernel's objects and their rules, independent of how threads run: the handle table, events, mutexes, semaphores, timers, address arbiters, memory blocks, threads as wait objects, the process and its resource limit.
- **Read first:** 3dbrew *SVC* and *Kernel objects*; in Azahar: `src/core/hle/kernel/handle_table.cpp`, `wait_object.cpp`, `event.cpp`, `mutex.cpp` (recursion, priority inheritance), `semaphore.cpp`, `timer.cpp`, `address_arbiter.cpp`, `shared_memory.cpp` (a block created at address 0 is allocated linearly from FCRAM), `resource_limit.cpp` (the APPLICATION category), `thread.cpp` (wait states and wake-up results), `errors.h` (result codes); `native/include/mh4n/memory.h` (N1-02).
- **Files (allowlist):** `native/include/mh4n/kernel.h`, `native/src/kernel/**`, `native/tests/kernel_objects_test.cpp`.
- **Spec:**
  - Objects are owned through `std::shared_ptr`; their types are Azahar's `HandleType`.
  - **`HandleTable`:**
    - 4096 slots; a handle is `generation | slot << 15`; one generation counter for the whole table, starting at 1 and wrapping from 2^15 back to 1; the last slot freed is the first reused. This is Azahar's scheme, so handle values match the reference when calls come in the same order;
    - pseudo-handles `0xFFFF8000` (current thread) and `0xFFFF8001` (current process);
    - `Create`, `Duplicate`, `Close`, `Get<T>`.
  - **Waiting:** `WaitObject` keeps its waiting threads, with `ShouldWait(thread)` and `Acquire(thread)`. Waking goes through a small `Scheduler` interface (`Wake(thread, result, index)`), so these objects work with a fake scheduler in the tests.
  - **The objects:**
    - Event: reset types `OneShot`, `Sticky`, `Pulse`;
    - Mutex: owner, recursion count, the error for a release by another thread, priority inheritance as Azahar;
    - Semaphore: count and maximum; release returns the previous count; the error past the maximum;
    - Timer: reset type, initial delay and interval, armed or not; `Fire()` is called from the scheduler's timer queue;
    - AddressArbiter: types 0–4 (Signal with a count, −1 meaning all; WaitIfLessThan; DecrementAndWaitIfLessThan; and their timeout variants), waiters woken in priority order as Azahar;
    - SharedMemory, two kinds: kernel-created blocks with host backing (HID, GSP, the shared font), and blocks the app creates over its own memory or, at address 0, from FCRAM through `FcramRegions::LinearAllocate` (as Azahar);
    - Thread, as a wait object: signalled when it exits;
    - Process: one, with Azahar's application process id;
    - ResourceLimit: the APPLICATION values of Azahar for the memory mode.
  - **`Kernel`**, the facade services use: create objects, add handles to the process, get objects by handle, `CurrentThread()`, `Post(fn)` (callable from any host thread), `ScheduleAt(tick, fn)` and `Cancel`, `Memory()`, `Clock()`. This WP declares `Post` and the timer functions; N1-06 implements them.
- **Done when:** ctest passes with a fake scheduler:
  - one test case per rule above, with the result codes;
  - handle numbering: after three creates and closing the second, the next create reuses slot 1 with generation 4 (handle `0x00008004`);
  - pseudo-handles.
- **Traps:** a kernel-created block lives in host memory until the app maps it. On the first map, copy its contents into the guest range, which becomes its home: services then reach it through the guest range. Mapping one block at two guest addresses at once is unsupported (log an error).
- **As built (N1-05), for N1-06, N1-07, N1-10 and N1-27** (the contract is `native/include/mh4n/kernel.h`):
  - `kernel.h` has no scheduler of its own. N1-06 implements the `Scheduler` interface: `Wake(thread, optional<Result>, index)` (an empty result means "leave r0 alone", as for sleep and IPC waits; `index >= 0` is `WaitSynchronizationN`'s output), `OnPriorityChanged(thread, old)` (called on every `SetPriority`, `BoostPriority` and `UpdatePriority`, also when nothing changed, for a thread in any state), `PrepareReschedule`, `CurrentThread`, `NowTicks`, `ScheduleAt(tick, fn)` (returns a non-zero id), `Cancel(id)` and a thread-safe `Post(fn)`; it then calls `Kernel::SetScheduler` and `SetClock`. `Kernel::Post`, `ScheduleAt`, `Cancel` and `NowTicks` are inline forwards to it. The header forward-declares `class GameClock;` for `Kernel::Clock()`: N1-06's clock class in `mh4n/clock.h` must be named `GameClock`, and `scheduler.h` must not define another `Scheduler`.
  - Thread API for blocking, sleeping and exiting: `BeginSynchWait(objects, wait_all)` (the caller has already checked `ShouldWait`), `ArmTimeout(ns)` (-1 never; it schedules `OnWaitTimeout` on the timer queue), `OnWaitTimeout()`, `ResumeFromWait(result, index)`, `Stop()` (the scheduler removes the thread from its queues first), `wake_hook` (Azahar's `WakeupCallback`, for IPC) and `scheduler_data` (an opaque slot). `ThreadWakeupReason::Terminated` is new (Azahar's `Stop` never calls the wake-up callback): N1-10's IPC hooks must tolerate it. Object factories are `Kernel::New*` (not `Create*`: `windows.h` defines macros of that name). `Kernel::NewThread` gives a bare dormant thread with ids from 1 (N1-27 adds stack, TLS and registers). The application's process id is 11.
  - Departures from Azahar, all deliberate: a thread's timeout event is cancelled when anything else wakes it (Azahar leaves it queued and it can wake the thread out of a later, unrelated wait); a handle whose slot field is 4096 or more is invalid (Azahar truncates the slot to 16 bits, so `0x80000002` aliases slot 0); `NewSharedMemory` at address 0 with no room returns `0xD86007F3` (Azahar asserts); `SharedMemory::Unmap` at an address where the block is not mapped returns `kResultInvalidAddressState` (Azahar unmaps whatever range it is given); mapping a block at a second address, or an app-created block anywhere, is logged and refused (host aliasing is unsupported, as above); a thread that ends while in an arbiter wait is dropped from the arbiter's list; `Semaphore::Release` tests the maximum in 64 bits (Azahar's `s32` sum can overflow); a periodic timer's interval is at least 1 tick; the 1614 extra ticks Azahar charges to an arbiter `Signal` that wakes nobody are not modelled. Resource-limit `Reserve`/`Release` always succeed and only log, as in Azahar.
- **Out of scope:** running threads (N1-06); decoding SVC arguments (N1-07).

### N1-06 · Scheduler, game clock and timers
- **Size / agent:** L · native-worker-high
- **Depends on:** N1-04, N1-05 · **Needs:** none
- **Goal:** guest threads run on fibers under our scheduler (D1): strict priority per virtual core, the 3DS's preemption rules, timeouts and timers on the game clock, host work applied at safe points, and the counters the CPU budget needs.
- **Read first:**
  - D1; [`../ROADMAP.md`](../ROADMAP.md) §3, principles 3 and 6;
  - `docs/research/kernel-census.md` (N0-12) if it exists: the threads and their cores;
  - in Azahar: `src/core/hle/kernel/thread.cpp` (`PopNextReadyThread` and `Reschedule`: no time slicing between equal priorities; `WakeAfterDelay`), `src/core/core.cpp` (`RunLoop`: how the cores share one host thread), the `SleepThread` case of `src/core/hle/kernel/svc.cpp` (what 0 ns does);
  - `native/include/mh4n/kernel.h` (N1-05) and `cpu.h` (N1-04).
- **Files (allowlist):** `native/include/mh4n/clock.h`, `native/include/mh4n/scheduler.h`, `native/src/kernel/**`, `native/tests/scheduler_test.cpp`.
- **Spec:**
  - **Virtual cores:** two (core 0, the application core, and core 1). Each has a ready queue per priority, 0 (highest) to 63, first in first out within a priority.
  - **Running:** a thread runs until it blocks, yields (SleepThread with 0 ns, as Azahar), exits, or a higher-priority thread on its core becomes ready. Equal priorities are not time-sliced.
  - **One host thread** runs both virtual cores (D1, for N1). Each core with ready threads gets a slice of `slice_us` (default 1000 µs; the runner's `--slice-us`, N1-09) in turn; a slice ends at the first preemption check after its time is up.
  - **Preemption:** the code library's `RC_TICK` checks `*preempt_flag`. The scheduler raises it:
    - from a timer thread, at the earliest deadline or at the end of a slice;
    - when `Post` queues host work;
    - when code running on one core makes a higher-priority thread ready on the other.

    `Preempt()` (the code host's `budget` callback) clears the flag, runs due timers and posted work, and switches threads if it should. An SVC that makes a higher-priority thread ready switches before returning to its caller, as Azahar's `PrepareReschedule` does.
  - **Waiting:** `Block(thread, objects, wait_all, timeout)`, on top of N1-05's wait objects, with timeouts on the timer queue and Azahar's wake-up results (the timeout result code; the index for a wait on any).
  - **Idle:** when no core has a ready thread, the host thread waits on a condition variable until the earliest deadline or posted work.
  - **Game clock** (`mh4n/clock.h`): ticks at 268,111,856 Hz from the host's monotonic clock, minus the time spent paused; `Pause()`, `Resume()`, and `Hold(until)` for net sync later; `Now()` in ticks and in ns. Conversions use 128-bit intermediates (`ns × 268111856` overflows 64 bits after about 68 s).
  - **Timer queue:** `ScheduleAt(tick, fn)` and `Cancel(id)`. Kernel timers fire from it, and so does the shared page's date-time update (N1-03).
  - **Safe-point hooks:** `OnSafePoint(fn)` registers a function the scheduler calls at every preemption point and every SVC (the runner's frame watcher uses it, N1-09).
  - **`mh4n/scheduler.h`**, what other modules use: run until the program exits or a predicate holds; `Block` and the wake-up results; `OnSafePoint`; `RunPending()`, which runs posted work and due timers without any guest fiber (the replay tool, N1-11); the slice length; the counters.
  - **Counters**, cumulative, for the runner to sample per game frame: time in guest code per thread, in SVCs by number, in services by name (N1-10 adds the names), idle time, thread switches, preemptions.
  - **Deterministic mode** comes in N1-25: keep the clock and the preemption sources behind an interface it can replace.
- **Done when:** ctest passes, with fibers running small C++ functions that call the scheduler's API directly (no code library):
  - a thread made ready at a higher priority runs first;
  - equal priorities run first in, first out; SleepThread(0) yields to them;
  - waits on any and on all, with and without timeouts;
  - arbiter waiters woken in priority order;
  - a periodic timer fires at its interval;
  - two cores, each with a busy thread, both make progress;
  - `Post` from another host thread wakes a waiting fiber;
  - clock conversions are exact at one year of ticks.
- **Traps:**
  - Never switch fibers from the signal handler or the timer thread. The timer thread only raises the flag and notifies the condition variable.
  - Fiber switches through `ucontext` cost a system call each. The counters will show whether that matters (N1-23).
- **As built (N1-06), for N1-07, N1-09, N1-10, N1-11, N1-14 and N1-25** (the contracts are `native/include/mh4n/clock.h` and `scheduler.h`):
  - `GameClock` (ticks at 268,111,856 Hz over a `TimeSource`; `Pause`, `Resume`, `Hold`) and `GuestScheduler(Kernel&, CodeHost&, GameClock&, TimeSource&, PreemptionSource*, Options)`. The real sources are `MakeTimerThreadPreemption(source)` and the host's monotonic `TimeSource`; `ManualTimeSource` (`Advance`, `Set`, `SetAdvanceHook`) is the deterministic one the tests and N1-25 use: with a deadline its `WaitUntil` jumps the time to it instead of waiting.
  - Threads: `Attach(thread, entry)` gives a thread its fiber (with no entry it runs the guest function at `Context().r[15]`), `AttachFunction` runs a C++ body and ends the thread, `Start` makes a Dormant thread Ready at the back of its queue. A thread ends through `ExitCurrent()` (the running one), `Terminate(thread)` (another one, or the running one as `ExitCurrent`) or `RequestStop()` (stops `Run`, not a thread).
  - Blocking, on the running thread only: `Block(thread, objects, wait_all, timeout_ns)` is WaitSynchronization1/N with Azahar's results and index (`WaitOutcome{result, index, blocked}`), `Park(thread)` waits for a wake-up the kernel arranged (the arbiter, IPC and HLE waits), `Sleep(ns)` is SleepThread (0 yields as Azahar, -1 waits for ever).
  - The SVC layer brackets every call with `BeginSvc(number)` / `EndSvc()` (or the RAII `SvcScope`), and a service handler with `BeginService(name)` / `EndService()` (`ServiceScope`). `BeginSvc` calls the safe-point hooks and starts the SVC's counters; `EndSvc` switches threads if a `PrepareReschedule` or the flag asks for it. A thread that blocks inside an SVC stays between the two.
  - Running: `Run(until, return_when_idle)` returns `Stopped`, `Idle` or `Failed` (the code host recorded a failure: exit status 4) and can be called again to continue; `RunPending()` applies posted work and due timers with no guest fiber (the replay tool). `OnSafePoint(hook)` hooks run on the scheduler's thread at every preemption point, SVC and turn of the host loop, and must not switch fibers; with one registered a running guest gets a preemption check at least once per slice. `PreemptFlag()` is the pointer the code library polls (`CodeLibrary::Load`'s `preempt_flag`); `RaiseFlag()` may be called from any thread.
  - `SetSelectionFilter(core, filter)` is the hook of the core-1 limiter (N1-27): called for each thread about to run from that core's queue, returning true keeps it back. `Counters()` is `SchedulerCounters` (guest time per thread, time and calls per SVC number and per service name, idle time, thread switches, preemptions, core switches, preemption checks), in nanoseconds of the `TimeSource`, read on the scheduler's thread.
  - Lifetime: the scheduler owns its threads until they are dead; timers and threads call back into it when destroyed, so the order of teardown is `Shutdown()`, then the kernel, then the scheduler (`Runtime` does exactly this).
- **Out of scope:** creating threads from the guest (N1-27); one host thread per core (N6); decoding SVCs (N1-07); deterministic mode (N1-25).

### N1-27 · Threads: creation, TLS and the core-1 time limit
- **Size / agent:** M · native-worker-high
- **Depends on:** N1-06 · **Needs:** none
- **Goal:** guest threads are created exactly as Azahar creates them (thread-local storage, registers, floating-point state, ids, the checks CreateThread makes), and application threads on core 1 get the time share Azahar gives them (D24).
- **Read first:** in Azahar: `src/core/hle/kernel/process.cpp` (TLS: slots of 0x200 bytes from `0x1FF82000`, eight per 4 KiB page, pages taken from the BASE region, the first free slot reused, near lines 449–505), `src/core/hle/kernel/thread.cpp` (`CreateThread`, the initial context, `SetupMainThread`, `CpuLimiterMulti` near lines 585–690), `src/core/hle/kernel/svc.cpp` (`CreateThread` near lines 1270–1320: the priority and processor checks, FPSCR `0x03C00000`), `src/core/hle/kernel/resource_limit.cpp` (`ApplyAppMaxCPUSetting`), `src/core/hle/kernel/kernel.cpp` (thread ids from 1, never reused); `docs/research/kernel-census.md` (N0-12) if it exists.
- **Files (allowlist):** `native/include/mh4n/threads.h`, `native/src/kernel/**`, `native/tests/threads_test.cpp`.
- **Spec:**
  - **`mh4n/threads.h`:** `CreateMainThread(const ProcessImage&)`, which reserves one thread from the resource limit first, as Azahar's `Process::Run` does, and applies the image's CPU setting as `ApplyAppMaxCPUSetting` does; `SetAppCpuTimeLimit(percent)` and its getter, for APT (N1-14).
  - **TLS:** each thread gets a 0x200-byte slot at `0x1FF82000 + 0x1000 × page + 0x200 × slot`; pages are mapped as needed, taken from the BASE region through `FcramRegions`; the first free slot is reused. `tpidruro` holds the slot's address (the IPC command buffer is at +0x80, N1-10).
  - **Initial state:** r0 = the argument, sp = the stack top, pc = the entry (Thumb if bit 0 is set), user mode; FPSCR `0x03C00000` for threads from CreateThread and `0x03C00010` for the main thread (from the `ProcessImage`, N1-03).
  - **Ids:** from 1 in creation order, the main thread first; never reused.
  - **CreateThread's checks**, in Azahar's order and with its result codes (`SVC::CreateThread`, then `KernelSystem::CreateThread`, which also refuses an entry address that isn't mapped): a priority above 63 is out of range; a priority numerically below the resource limit's priority value (a higher priority than allowed) is not authorised, unless the process has no thread restrictions; processor −2 means the process's ideal processor, −1 means core 0, 0 and 1 are valid; anything else from 4 up, and below −2, is out of range; the resource limit's thread count. Processors 2 and 3 are New 3DS cores: Azahar lets them through and then indexes a core that doesn't exist on an Old 3DS, so the native runtime answers them as out of range (the conformance programs don't test them).
  - **The core-1 time limit** (D24): application threads on core 1 run under the limit APT sets (`SetAppCpuTimeLimit`), alternating as Azahar's `CpuLimiterMulti` does; without a limit, as Azahar without one.
- **Done when:** ctest passes: TLS slot addresses and reuse; initial registers and FPSCR; ids; each CreateThread check with its result code (processors 2 and 3 included); the limiter's alternation against a sequence worked out from Azahar's algorithm.
- **Traps:** the TLS area is also where the IPC layer finds each thread's command buffer and static receive buffers; keep its addresses exactly as Azahar's.
- **As built (N1-27), for N1-07, N1-09 and N1-14** (the contract is `native/include/mh4n/threads.h`):
  - `ThreadManager(Kernel&, GuestScheduler&)`. `CreateMainThread(image, &thread, host_entry)` runs after `Loader::Map`. `CreateThread(ThreadSpec{entry, arg, stack_top, priority, processor_id}, &handle, &thread)` is everything SVC 0x08 does after decoding its registers (r0 priority, r1 entry, r2 argument, r3 stack top, r4 processor). The result codes `kResultOutOfRange` (`0xE0E01BFD`), `kResultNotAuthorized` (`0xD9001BEA`), `kResultInvalidEntryAddress` (`0xD8E007F5`) and `kResultOutOfThreads` (`0xC860180C`) are in `threads.h`: N1-07 must not redefine them. Processors 2 and 3 answer `kResultOutOfRange`.
  - ExitThread is `GuestScheduler::ExitCurrent()`; `Thread::Stop` then gives the resource limit's thread count back, and the TLS slot is free when its thread is Dead. `CommandBufferAddress(thread)` is the slot plus `0x80`.
  - APT's SetAppCpuTimeLimit/GetAppCpuTimeLimit are `ThreadManager::SetAppCpuTimeLimit(percent)` (always success; a value above the CPU-time limit is ignored, as `PM_APP::UpdateResourceLimit`) and `AppCpuTimeLimit()`. `svcControlProcess` with `PROCESSOP_DISABLE_CREATE_THREAD_RESTRICTIONS` is `SetNoThreadRestrictions(true)`. The manager installs the scheduler's core-1 selection filter. Lifetime order: `Shutdown()`, the `ThreadManager`, the kernel, the scheduler.
  - Choices the spec left open: (1) `SVC::CreateThread` reserves the thread before the entry check and does not give it back on failure, as Azahar; `ResourceLimit::Reserve` never refuses, so `kResultOutOfThreads` cannot occur. (2) Azahar's 2.6 s sleep of the first application's main thread (the LLE module start) is not modelled. (3) The TLS bitmap and the no-thread-restrictions flag live in `ThreadManager`, because `kernel.h` has no place for them; moving them into `Process` would be a `kernel.h` change. (4) `GuestScheduler::Wake` keeps an earlier outcome when a later wake-up has no result and no index (`scheduler.cpp`, N1-06's code, a test pins it): without it a thread woken by a signal and then held back by the limiter returned to the guest with r0 and the WaitSynchronizationN index lost.
- **Out of scope:** decoding SVC arguments (N1-07).

### N1-07 · The SVC table
- **Size / agent:** M · native-worker-high
- **Depends on:** N1-02, N1-27 · **Needs:** none
- **Goal:** every SVC the game uses, decoded from and encoded into registers as the 3DS kernel does (per 3dbrew, with Azahar as the reference for edge cases), on top of N1-05, N1-06 and N1-27.
- **Read first:** 3dbrew *SVC*; in Azahar `src/core/hle/kernel/svc.cpp` (the wrappers' register use, result codes, the ControlMemory operations, CreateMemoryBlock at address 0); `docs/research/system-services.md` (the SVCs in the game's code); `docs/research/kernel-census.md` (N0-12) if it exists, for the arguments and info types in use; `tools/recomp/runtime/recomp.h` (`rc_svc(ctx, imm, next_pc)`); `port/src/arm_recomp.cpp` (`Svc`: `next_pc & ~1u` goes in r15).
- **Files (allowlist):** `native/include/mh4n/svc.h`, `native/src/kernel/**`, `native/tests/svc_test.cpp`.
- **Spec:**
  - **`mh4n/svc.h`:** the tracing hooks below, and the handlers the IPC layer installs for ConnectToPort and SendSyncRequest (N1-10).
  - **Dispatch:** `CallSvc(ctx, imm, next_pc)` sets `ctx->r[15] = next_pc & ~1u` (for traces and failure reports, as the Azahar backend does), decodes the arguments, runs the call and writes the outputs.
  - **The SVCs** (the census, if it exists, may add some; N1-21 catches any left):

    | SVC | Name | Notes |
    |---|---|---|
    | 0x01 | ControlMemory | ALLOC with and without the linear flag `0x10000`, FREE, PROTECT, COMMIT as Azahar; MAP/UNMAP: `needs-decision` if the game uses them |
    | 0x02 | QueryMemory | |
    | 0x03 | ExitProcess | ends the run (exit status 0) |
    | 0x08 | CreateThread | r0 priority, r1 entry, r2 argument, r3 stack top, r4 processor id; out r1 the handle; the rules of N1-27 |
    | 0x09 | ExitThread | |
    | 0x0A | SleepThread | r0/r1 hold an `s64` in ns |
    | 0x0B, 0x0C | Get/SetThreadPriority | |
    | 0x13, 0x14 | CreateMutex, ReleaseMutex | |
    | 0x15, 0x16 | CreateSemaphore, ReleaseSemaphore | |
    | 0x17–0x19 | CreateEvent, SignalEvent, ClearEvent | |
    | 0x1A–0x1D | CreateTimer, SetTimer, CancelTimer, ClearTimer | |
    | 0x1E–0x20 | CreateMemoryBlock, MapMemoryBlock, UnmapMemoryBlock | a block at address 0 comes from FCRAM, linearly (N1-05) |
    | 0x21, 0x22 | CreateAddressArbiter, ArbitrateAddress | the timeout in r4/r5 |
    | 0x23 | CloseHandle | |
    | 0x24, 0x25 | WaitSynchronization1, WaitSynchronizationN | |
    | 0x27 | DuplicateHandle | |
    | 0x28 | GetSystemTick | out r0/r1, a `u64` |
    | 0x29 | GetHandleInfo | |
    | 0x2A–0x2C | GetSystemInfo, GetProcessInfo, GetThreadInfo | the types 3dbrew documents for applications, with Azahar's values (the census, when it exists, says which the game asks for) |
    | 0x2D | ConnectToPort | through the port registry of N1-10; until then, Azahar's error for an unknown port |
    | 0x32 | SendSyncRequest | handed to the IPC layer (N1-10) |
    | 0x35, 0x37 | GetProcessId, GetThreadId | |
    | 0x38–0x3A | GetResourceLimit, …LimitValues, …CurrentValues | |
    | 0x3C | Break | ends the run with a report (exit status 3) |
    | 0x3D | OutputDebugString | |

  - **Unknown SVCs:** log `unimplemented svc 0x<n> at <lr>` once per number and leave the registers as they are (Azahar's behaviour).
  - **Tracing:** a hook before each SVC and one when it completes for the calling thread: at once for calls that return, at the thread's next run for calls that block. The runner writes N0-04's SVC trace from them (`in4=`, `out=` and the thread lines).
- **Done when:** ctest passes: for each SVC, the register encoding and the result codes, through a fake guest context; a blocking call's completion hook fires when the thread resumes. (The conformance programs run in N1-09.)
- **Traps:** ControlMemory's linear allocations must go through `FcramRegions` (N1-02), or their addresses won't match the reference.
- **As built (N1-07), for N1-09, N1-10, N1-14 and N1-21** (the contract is `native/include/mh4n/svc.h`):
  - `SvcTable(Kernel&, GuestScheduler&, ThreadManager&)`; `Install(CodeHost&)` sets the code host's SVC handler; `CallSvc(ctx, imm, next_pc)` is the dispatch. Unknown SVCs are logged once per number and leave the registers alone. Beyond the table: `0xB3` ControlProcess op 7 is `SetNoThreadRestrictions`; other ops answer `0xE0E01BF4`.
  - Tracing: `SetHooks({before, complete, thread_created, debug_string})`. `before` gets an `SvcCall{thread_id, number, pc (r15), lr, r0-r6, ticks}` (the trace line and `in4=`); `complete(call, r0-r3)` gives `out=`, at once or when the blocked thread runs again; `thread_created` fires just before `complete` for a successful CreateThread (the `# thread` line: parent, id, entry, argument, stack, priority, requested and resolved processor); the main thread's line comes from the `Thread` that `CreateMainThread` returns. `PendingCalls()` lists the calls that never completed (written with `out=-`). `Exit()`: ExitProcess ends the run with status 0, svcBreak with status 3 and a report; both `RequestStop` and end the calling thread.
  - For N1-10: `SetConnectToPortHandler(name, &session object)` (the table adds the handle) and `SetSendSyncRequestHandler(Thread&, Handle -> Result)`; to block, the handler sets `thread.status = WaitIPC` (plus a wake hook if needed) and returns: the table parks the thread and r0 is the wake-up's result or, if none, the handler's.
  - For N1-09 and N1-14 (the conformance programs): the process must be created at a game tick above 0 (`Process::creation_time_ticks`, GetHandleInfo type 0) and something must allocate from the SYSTEM region (the HID and GSP shared-memory blocks) for `sysinfo.memory_region2.nonzero` of `conf_info`. `conf_mem` (N1-05 does not alias shared-memory pages) and `conf_srv`/`conf_services` (N1-10, N1-15) go in N1-09's `NATIVE_NOT_YET`. On a scratch harness (the worker's, not committed) conf_sync, conf_wait, conf_arbiter, conf_timer and conf_sched gave Azahar's expected output.
  - Departures from Azahar, to confirm against the census or the dump: (1) ControlMemory MAP and UNMAP check their arguments as Azahar does and are then refused with `0xE0A01BF5` and logged once (flat memory cannot alias); the spec's `needs-decision if the game uses them` stays open until N0-23 or the dump say whether it does. (2) `OutOfHeapMemory` is `0xC8601BF3`, what Azahar's arguments compute and `conf_mem.txt` shows, not the `0xC860180A` of its comment. (3) The outputs of a failed call, and r1 of a WaitSynchronizationN that sets no index, are written as 0 (`conf_wait.txt` reads 0). (4) GetResourceLimitCurrentValues refuses a name of 10 or more with `0xD8E007ED` (Azahar indexes out of bounds). (5) OutputDebugString ignores a length over 1 MiB. (6) ControlMemory FREE of loader-mapped memory unmaps it without returning its FCRAM (only ControlMemory's own pieces are tracked). (7) GetSystemInfo `0x20000` (Azahar's own info) answers as an unknown type. `SharedMemory::Map` (N1-05) answers a misaligned address with `0xE0A01BF5` instead of asserting.
- **Out of scope:** ports and sessions (N1-10).

### N1-08 · Kernel conformance programs
- **Size / agent:** M · native-worker
- **Depends on:** N0-04 · **Needs:** none (it uses the reference runner artifact)
- **Goal:** our own 3DS programs that exercise the kernel's rules and print deterministic results, with Azahar's output committed as the expected output: the public oracle for N1's kernel and for the first services.
- **Read first:** `port/tests/svc_test.c`, `svc.h` and `build_svc_test.py`; `tests/test_port.py` (how outputs are extracted and compared); 3dbrew *SVC*; `docs/native/CI.md` (fetching the reference runner).
- **Files (allowlist):** `port/tests/conf_*.c` (new), `port/tests/svc.h` (more SVC wrappers), `port/tests/build_svc_test.py` (build any program by name), `port/tests/expected/*.txt` (new), `tests/test_conformance.py` (new).
- **Spec:**
  - **Programs**, one per file. Each prints one line per check (`<check>: <value>`), ends with `<program>: done` and calls ExitProcess:
    - `conf_sync`: events of each reset type with waits (signalled, consumed); mutex recursion and a release by another thread (result code); semaphore counts and a release past the maximum (result code);
    - `conf_wait`: WaitSynchronization1 and N: timeout 0 on an unsignalled object (result code), the index of a wait on any, a wait on all, finite timeouts, an invalid handle (result code);
    - `conf_arbiter`: the five arbitration types, signal counts 1 and −1, timeouts;
    - `conf_timer`: one-shot, sticky and pulse timers with intervals: whether each fires, and whether a periodic one fired at least N times within a generous wait (print the threshold result, never a count), cancel and clear;
    - `conf_sched`: a higher-priority thread created runs before CreateThread returns; equal priorities first in, first out; SleepThread(0) yields; Get/SetThreadPriority; waiting on a thread handle until the thread exits; CreateThread's checks with their result codes: priority 64, and processor 4 (out of range; 2 and 3 would make Azahar index a core an Old 3DS doesn't have);
    - `conf_mem`: ControlMemory heap and linear allocations and frees, with the returned addresses; QueryMemory of the code, the heap, the stack, the linear heap and an unmapped address (base, size, permission, state); memory blocks over the program's own memory and at address 0;
    - `conf_info`: GetSystemTick is monotonic (print only that); GetSystemInfo and GetProcessInfo for the types 3dbrew documents for applications; the resource-limit values; GetThreadId and GetProcessId; DuplicateHandle; closing a handle twice (result code); GetHandleInfo;
    - `conf_srv`: `srv:` RegisterClient; GetServiceHandle for `cfg:u` and `ptm:u`, and for an unknown name with flags = 1 (don't wait; with bit 0 clear, Azahar waits forever); EnableNotification; the result codes;
    - `conf_services`: one simple request each to `cfg:u` (GetConfigInfoBlk2: language, region, user name length), `ptm:u` (battery level, adapter state) and `ac:u` (connection status), printing the results.
  - **Determinism:** every line must be the same on every run under the 3DS's scheduling rules. Print after joins, not from racing threads, and never print raw tick values or counts that depend on timing.
  - **Expected outputs** (for every `conf_*` program and for the existing `svc_test`): run each program with the reference runner (`--cpu jit --new-3ds off`, from the `mh4u-runner-linux` artifact), keep the text of the `OutputDebugString` lines in `port/tests/expected/<program>.txt` (the number after `OutputDebugString:` in Azahar's log is its source line, not part of the output), and run again to confirm they are stable.
  - **`tests/test_conformance.py`**, for each program:
    - it builds and recompiles cleanly (always);
    - with `MH4U_RUNNER` set, the `--cpu jit --new-3ds off` output equals the expected file;
    - with `MH4N_RUNNER` set, the native runner's output equals it, except for the programs listed in the file's `NATIVE_NOT_YET` set (N1-09 fills it in).
- **Done when:**
  - `python3 -m pytest tests/test_conformance.py` passes without runners (the build checks);
  - with `MH4U_RUNNER` set to the artifact's runner, every program matches its expected file, twice in a row.
- **Traps:**
  - These are our own programs: never paste game code. Keep each under 300 lines.
  - Azahar gives ELF programs kernel version 0x23A, so their linear allocations land from `0x30000000` up, and memory mode Dev1.
- **Out of scope:** the native side (N1-09, N1-10, N1-15).

### N1-09 · The runtime, the native runner and the first boot
- **Size / agent:** L · native-worker-high (it defines contracts most of N1 builds on)
- **Depends on:** N1-03, N1-07, N1-08, N0-08 · **Needs:** ci
- **Goal:** a `Runtime` that boots a program on the native modules, and `mh4u_native_runner` around it: a 3DS ELF test program prints the same output as on Azahar, and `svc_test` and the kernel conformance programs pass, locally and in CI. Later modules add their options, devices, services and traces to it without editing it.
- **Read first:** `port/README.md` (mh4u_runner's options); `port/src/runner.cpp` (its exit statuses, near lines 1033 and 1095–1110; the fixed start date near line 980); `port/src/schedule.h` (N0-08); `tests/test_conformance.py`; the public headers in `native/include/mh4n/` (`options.h` and `registry.h` especially).
- **Files (allowlist):** `native/include/mh4n/runtime.h` (new), `native/include/mh4n/host.h` (new), `native/src/runtime/**` (new; its `CMakeLists.txt` compiles `port/src/schedule.cpp`, which other modules then use through `mh4n_runtime`), `native/runner/**`, `native/tests/runtime_test.cpp`, `tests/test_conformance.py` (how the native runner is called, and `NATIVE_NOT_YET`), `.github/workflows/native.yml` (the `native` job also runs `tests/test_conformance.py` with `MH4N_RUNNER`), `docs/native/runner.md` (new).
- **Spec:**
  - **`mh4n/host.h`:** what the runtime gives the services from the host:
    - `InputState` (the 3DS PAD bits as hid's shared memory has them, circle pad x and y, touch down/x/y, C-stick x and y and ZL/ZR for the Circle Pad Pro, accelerometer and gyroscope) and `InputSource { virtual InputState Sample(u64 tick) = 0; }`;
    - `AudioSink { virtual void Queue(const s16* stereo, std::size_t frames) = 0; }`;
    - `HostInterfaces { gpu::Gpu* gpu; InputSource* input; AudioSink* audio; }`;
    - `using InputSourceFactory = std::function<std::unique_ptr<InputSource>(Runtime&)>;` and the same for `AudioSinkFactory`, registered by name like `gpu::GpuFactory` (a factory reads its options and subscribes to frames through the `Runtime`).
  - **`mh4n/runtime.h`, `native/src/runtime/`:** `Runtime` owns the guest memory, the kernel, the code host, the loaded program, the `Options` and the `HostInterfaces`.
    - `Boot(options)`: load the program (N1-03); create the process and the main thread (N1-27); load and check the code library (N1-04); run the boot steps; then run the scheduler until the program exits or a limit is reached.
    - **Boot steps:** `struct BootStep { Phase phase; std::function<void(Runtime&)> run; };`, registered by name (`MH4N_REGISTER(BootStep, …)`), run in phase order and then by name: `devices` (the host interfaces), `services` (ports and services, N1-10), `tracing` (traces and captures), `started` (after the main thread exists, before it runs).
    - **`Prepare(options, phases)`:** guest memory, the kernel and the process, and only the boot steps of the given phases, with no program and no code library: what the replay tool needs (N1-11).
    - **`OnFrame(fn(frame, tick))`:** subscribers the frame watcher calls when the frame counter changes (frame-keyed input, `--set fN`, captures, the perf log).
    - **Sinks other modules fill:** `SetGpuInterruptSink(fn(gpu::Interrupt))` (GSP sets it, N1-17; the runtime's `gpu::Host` posts each interrupt to the kernel and calls the sink on the scheduler thread) and `SetRefreshRateSink(fn(double))` with `SetRefreshRate(double hz)` (GSP sets the sink; the platform calls it, N1-20).
    - The runtime's own `devices` step creates the GPU, input source and audio sink named by `--gpu` (default `null`), `--input-source` (default `script`) and `--audio` (default `null`) from their registries; a name nothing has registered yet leaves that interface empty, with an Info line. The GPU's `Host` is the runtime's (guest memory's physical view, interrupts and `Post` through the kernel).
    - A **frame watcher** on the scheduler's safe points (N1-06) reads the frame counter (`0x010571d4`) and drives `--frames`, `--state-trace` and the `OnFrame` subscribers.
  - **The runner's own options** (`runner` scope), with mh4u_runner's names:
    `mh4u_native_runner PROGRAM --code LIB [--ms N] [--frames N] [--log FILTER] [--trace-svc FILE] [--state-trace FILE] [--observable FILE] [--slice-us N] [--user DIR] [--init-time SECONDS] [--print-process] [--gpu NAME] [--input-source NAME] [--audio NAME]`.
    - **PROGRAM** is an ELF or a game folder (N1-03).
    - `--trace-svc` in N0-04's format, with the header and thread lines; `--state-trace` in N0-07's format (the frame watcher writes a line when the counter changes); `--init-time` goes to the shared page (N1-03; default 1767268800).
    - Options other modules register appear in `--help` by themselves; `docs/native/runner.md` says so, and lists the runner's own.
  - **Output:** debug strings as `OutputDebugString:0: <text>`, so the tests' regex reads both runners. The exit statuses are the ones at the top of this file.
  - **`tests/test_conformance.py`:** the native runner's path comes from `MH4N_RUNNER` and nothing in the test assumes a platform, so the Windows and macOS jobs (N1-22) run it unchanged. `NATIVE_NOT_YET = {"conf_srv", "conf_services"}` (N1-15 takes both out: they need cfg and ptm).
- **Done when:**
  - ctest passes, including: a boot step of each phase registered from the test and run in order; `Prepare` with two phases and no program; an `OnFrame` subscriber called as a fake frame counter changes; an interrupt reaching the sink through the runtime's `gpu::Host`; the runtime's `gpu::Host::PhysicalPointer` gives the same answers as `CaptureHost` at the edges of an area (the whole range or null; size 0 probes the address, one past the end of an area included): the cases of `gpu_gx_test.cpp`'s "bounds: Window" for VRAM, DSP RAM and the 128 MiB FCRAM, copied into `runtime_test.cpp` (the allowlist has no shared header) and run against it (`CaptureHost`'s New 3DS FCRAM up to `0x30000000` is not required of the runtime's `Host`: `GuestMemory`'s FCRAM ends at `0x28000000`);
  - `MH4N_RUNNER=… python3 -m pytest tests/test_conformance.py` passes for `svc_test` and every `conf_*` program outside `NATIVE_NOT_YET`;
  - `compare_svc_traces.py --normalize --outputs --ignore-regs config/native/svc_unused_registers.txt` finds `svc_test`'s native and reference traces equal. (The rule file lists registers a call neither reads nor writes: `svc_test` leaves a partial sum, which depends on the order its workers run in, in r1 at ReleaseMutex, and Azahar charges instruction time while the native clock is the host's. N1-25's deterministic mode compares without the rules. Added by the orchestrator after N1-09's worker showed the unfiltered comparison cannot hold in real time.)
  - *(CI)* the `native` job runs the conformance programs and is green.
- **Traps:** test programs need code libraries built with `--native`; use the helper in `tests/test_conformance.py`.
- **As built (N1-09), for N1-10, N1-11, N1-14, N1-17, N1-19 and N1-25** (the contracts are `native/include/mh4n/runtime.h` and `host.h`; the runner's options are in `docs/native/runner.md`):
  - `Phase` and `BootStep` are namespace-level (`mh4n::Phase`, `mh4n::BootStep`); a step is registered `MH4N_REGISTER(BootStep, name, BootStep{Phase::X, fn})`. `Boot` returns the exit status. `Prepare(options, phases)` is what the replay tool (N1-11) calls: `Prepare(options, {Phase::Devices, Phase::Services})` and then `rt.Scheduler().RunPending()`. `Runtime::SetMainThreadEntry` lets a test boot an ELF whose main thread runs a C++ function, with no code library.
  - For services (N1-10 and on): a `services` step sets `rt.Svc().SetConnectToPortHandler` and `SetSendSyncRequestHandler`; a `ServiceContext` is built from `rt.GameFolder()`, `UserFolder()`, `GetOptions()`, `GetKernel()` and `Interfaces()`; `err:f` ends the run with `rt.RequestExit(3, reason)`. `--trace-ipc` uses `rt.AddSvcHooks` (`thread_created`), `rt.MainThread()` for the `parent=0` line and `rt.OnFinish` to close. GSP uses `SetGpuInterruptSink`, `SetRefreshRateSink` and `rt.GpuHost()`; input and audio register an `InputSourceFactory` or `AudioSinkFactory`.
  - Time: the game clock is stopped once the world is built and runs again when the scheduler starts; it keeps the ticks of the setup (host-dependent, a few tens of thousands), so the traces' `t=` starts there and the process is created at a tick above 0, as N1-07 needs. N1-25's deterministic mode will start it at a fixed value. The default `--ms` is 10000 and `--frames` alone means no time limit, as `mh4u_runner`. `--print-process` is a flag on the positional PROGRAM. `gpu::Host::PhysicalPointer` accepts the end of FCRAM, VRAM and DSP RAM for size 0 even where the linear heap is not mapped. `port/src/schedule.cpp` is compiled into `mh4n_runtime` only when it exists next to `native/` (a lone copy of `native/` parses `--ms` and `--frames` itself, which `test_native_cmake_layout.py` exercises).

  - The svc_test trace comparison cannot hold in real time without the rule file (see the Done-when): checked on 12 runs, also under load, with `--ignore-regs config/native/svc_unused_registers.txt`, and on 10 runs without it, where it fails only at ReleaseMutex r1.
- **Out of scope:** running the game (N1-21).

### N1-10 · IPC core, ports, sessions and srv
- **Size / agent:** M · native-worker-high
- **Depends on:** N1-07, N1-09, N0-21 · **Needs:** none
- **Goal:** SendSyncRequest reaches HLE services written against one small API, with the 3DS's command-buffer translation; plus the `srv:` and `err:f` services.
- **Read first:** 3dbrew *IPC*, *Services API* and *srv*; in Azahar: `src/core/hle/ipc.h`, `src/core/hle/kernel/hle_ipc.cpp` (translation; static buffers received through the descriptors at TLS + 0x180), `src/core/hle/service/service.cpp` (named ports; what an unimplemented command gets back), `src/core/hle/service/sm/srv.cpp` (GetServiceHandle and its wait flag), `src/core/hle/service/sm/sm.cpp`, `src/core/hle/service/err/err_f.cpp`; `tools/compare_ipc_traces.py` (N0-21: the IPC trace format); `native/include/mh4n/runtime.h` and `host.h` (N1-09).
- **Files (allowlist):** `native/include/mh4n/ipc.h`, `native/include/mh4n/service.h`, `native/src/ipc/**`, `native/src/services/srv/**`, `native/src/services/err/**`, `native/tests/ipc_test.cpp`, `native/tests/srv_test.cpp`.
- **Spec:**
  - **Ports:** two named ports, `srv:` and `err:f`, installed by a `services` boot step as Azahar installs them. ConnectToPort gives a client session handle.
  - **Sessions:** a client object (in the app's handle table) paired with a server side, a `Service` instance (per session, sharing state per service as the service needs).
  - **`Service`** (`mh4n/service.h`): a name and a table from command id (`header >> 16`) to handler. Services register a `ServiceFactory` by name (`MH4N_REGISTER(ServiceFactory, "fs:USER", …)`); a factory gets a **`ServiceContext`**: the game folder, the user folder, the `Options`, `Kernel&` and the `HostInterfaces&`, so services need nothing from the runner.
  - **`Request`** (`mh4n/ipc.h`):
    - typed access to the header, the normal words and the translated descriptors: handles in; static buffers in (guest address and size, read through `GuestMemory`); mapped buffers (address, size, permission, validated against the mapping); the calling PID;
    - a reply builder: the result, normal words, handles out (copied or moved into the client's handle table), static buffers out (copied into the client's receive buffer described at its TLS + 0x180 + 8 × index), the PID.
  - **Deferred replies** (D22): a handler may return `Deferred`. The requesting thread then blocks until `Complete(request, reply)` is posted (from any host thread, through `Kernel::Post`), and the reply is written into its command buffer on the scheduler thread.
  - **Unknown commands:** logged once as `unimplemented <service> <header>` and answered as Azahar's service framework answers them.
  - **`srv:`:** RegisterClient; EnableNotification (a semaphore handle); GetServiceHandle (a new session of the registered service; for an unregistered name, with flag bit 0 set Azahar's error, with it clear the thread waits until the service registers, as Azahar); Subscribe, Unsubscribe, ReceiveNotification (nothing pending) and PublishToSubscriber as Azahar.
  - **`err:f`:** ThrowFatalError: log the fatal-error information as Azahar does (type, result code, PC, LR, the message for the type that has one), then stop the run with exit status 3.
  - **Tracing:** `--trace-ipc FILE` and the `--trace-ipc-full` flag (registered here, in the `runner` scope), in N0-21's format, from a `tracing` boot step.
- **Done when:** ctest passes: header and descriptor decoding and encoding (copied and moved handles, static and mapped buffers, the PID); a static-buffer reply into a receive buffer; a deferred reply completed from another host thread; the `srv:` flows (register, get a handle of a service registered by the test, an unknown name with each flag); a fatal error through `err:f`. (`conf_srv` needs cfg and ptm: N1-15 runs it.)
- **Traps:** handle descriptors can carry several handles; the count is in the descriptor.
- **As built (N1-10), for N1-11, N1-12, N1-14, N1-15, N1-17 to N1-19 and N1-21** (the contracts are `native/include/mh4n/ipc.h` and `service.h`; the tests are `ipc_test` and `srv_test`):
  - **Module `mh4n_ipc`.** The boot step `services.ipc` makes one `ServiceManager` per runtime (`rt.Own`), installs every entry of the `Registry<ServiceFactory>` and sets the SVC layer's ConnectToPort and SendSyncRequest handlers; `FindServiceManager(rt)` returns it to a tool that used `Runtime::Prepare(options, {Devices, Services})`. Services register with `MH4N_REGISTER(ServiceFactory, "fs:USER", ServiceFactory(lambda, max_sessions))` (reached through `srv:` GetServiceHandle; names of 1 to 8 characters) or `ServiceFactory::NamedPort(...)` (`svcConnectToPort`; `srv:` has 64 sessions, `err:f` 1). `max_sessions` defaults to 10 (Azahar's `DefaultMaxSessions`); a full port answers `0xD0401834` (GetServiceHandle gets that error, it does not wait); the count drops when the client closes its last handle.
  - **A service** is `class Foo : public Service`: the constructor calls `Service(ctx, "name")`, `Register(id, "Name", &Foo::Fn)` takes `void Fn(Request&)` or `Handled Fn(Request&)`, and `Register(id, "Name")` declares a known command with no handler. There is one `Service` instance per session; state shared by the sessions is `Context().State<T>(key)`; sub-sessions (a file, a directory) are made with `Context().CreateSession(std::make_unique<...>(...))` and pushed with `PushMoveObjects`; override `SessionKind()` (`file`, `dir`) so traces name them `<service>/file#k`. `ServiceContext` gives `GameFolder`, `UserFolder`, `GetOptions`, `GetKernel`, `Memory`, `Scheduler`, `Threads` (the `ThreadManager`, for APT), `Interfaces`, `Services` and `RequestExit(status, reason)`.
  - **`Request`** mirrors Azahar's HLE protocol: `Pop<T>`, `PopRaw<T>`, `PopGenericObjects<N>`, `PopObject<T>`, `PopObjects<T...>`, `PopPid`, `PopStaticBuffer` (the bytes are copied when the request is made, so a late reply sees what was sent) and `PopMappedBuffer` (`Read`/`Write` check permission, range and mapping, and may be called from an I/O thread while the client waits). `MakeReply(normal, translate)` returns a `Reply&`: `Push` of ints, bool, float and enums, `PushRaw`, `PushCopyObjects`/`PushMoveObjects`, `PushStaticBuffer(bytes, id)` (into the client's receive buffer at TLS + 0x180 + 8 x id), `PushMappedBuffer`, `PushPid`. A handle descriptor can carry several handles (the count is in the descriptor); every moved handle is closed in the client.
  - **Deferred replies (D22):** a handler returns `Handled::Deferred`, keeps `request.Share()` and later calls `Complete(request, Reply(request->CommandId(), normal, translate))` from any host thread; that goes through `Kernel::Post`, the reply is written on the scheduler thread and the client resumes. A client thread that ended meanwhile cancels the request. A request ends on the scheduler thread: at the end of Deliver (reply written, reply dropped or already finished), in `Cancel()` and after an immediate reply, the IPC layer calls `Request::ReleaseKernelObjects()`, which lets go of the client thread, process and session, the objects the client moved or copied in, the `Reply` and the replied hook, in locals that die on the scheduler thread. After that `Session()`, `ClientThreadPtr()` and `IncomingObjects()` are empty, `HasReply()` is false and `ClientThread()` must not be called (`ClientThreadId()` stays valid); a `Share()` copy can be dropped on any host thread once `Finished()`; `Finished()` and `Cancelled()` are atomic and may be polled from any thread. A service that drops its copy without ever calling `Complete` leaves the client waiting.
  - **Immediate replies** are written at once and the client then waits `kIpcReplyDelayNs` = 39000 ns of game time (status WaitIPC with a timeout, Azahar's `IPCDelayNanoseconds`, so a thread that only calls services cannot starve lower priorities). `ServiceManager::SetReplyDelayNs(0)` turns it off: N1-11's scratch thread uses `SendSyncRequest(Thread&, Handle)`, which leaves a thread that is not Running in WaitIPC for the caller to park (the thread must be attached to the scheduler for the wake-up).
  - **Unknown commands** (and ones registered without a handler) are logged once per (service, header) as `unimplemented <service> 0x<header> (command 0x<id>[, Name])`, and answered `(id << 16) | 0x40, 0`.
  - **`srv:`:** 1 RegisterClient, 2 EnableNotification, 5 GetServiceHandle (flag bit 0 clear and the service not registered: the client waits for `ServiceManager::RegisterService`, as Azahar; `conf_srv` avoids it), 9 Subscribe, 0xA Unsubscribe, 0xB ReceiveNotification (nothing pending: reply `0x000B0040, 0`, what Azahar's unimplemented path sends), 0xC PublishToSubscriber (0x203 = power off ends the run with status 0, as Azahar's `RequestShutdown`); RegisterService and the other server-side commands are answered as unknown. **`err:f`:** ThrowFatalError logs as Azahar does, replies success and calls `RequestExit(3, reason)`; SetUserString is unimplemented.
  - **Tracing:** `--trace-ipc FILE` and `--trace-ipc-full` (runner scope, tracing step `tracing.ipc`) write N0-21's format; session names are `srv:`, `<service>/<kind>#k` and `unnamed#k`; `t=` is game-clock ticks; requests that failed translation have `cmd=-`, requests with no reply at the end `out=-`. `conf_srv` on the native runner, with empty `cfg:u`/`ptm:u` stand-ins, gives `expected/conf_srv.txt` exactly and an IPC trace that `compare_ipc_traces.py --strict` finds equal to the reference runner's (handle values too). `conf_srv` stays in `NATIVE_NOT_YET` until N1-15 adds `cfg:u` and `ptm:u` and removes it from the set. No reply of `srv:` or `err:f` depends on time, so `config/native/ipc_time_dependent.txt` has no entry from N1-10.
  - **Departures from Azahar** (all in the headers): every handle of a move descriptor is closed (Azahar compares the whole word with `MoveHandle`, so descriptors with more than one handle leave them open); malformed commands (too long, cut off, unknown descriptor, handle not in the table) fail `svcSendSyncRequest` with `0xD9001830` / `0xD8E007F7` instead of asserting; a static reply bigger than the client's receive buffer is written short and logged; GetServiceHandle on a full port answers the error; the notification semaphore belongs to the session; the FPEXC line of `err:f` logs `fpexc` (Azahar prints `fpinst`); the reply has its own storage.
- **Out of scope:** the other services.

### N1-11 · IPC replay harness
- **Size / agent:** M · native-worker
- **Depends on:** N1-10, N0-21 · **Needs:** dump-check
- **Goal:** `mh4n_ipc_replay` replays the requests of a golden session's IPC trace against the native services alone and reports the first difference per service, so services can be built and checked without running the game.
- **Read first:** `tools/native/tracefmt.py` and `tools/compare_ipc_traces.py` (N0-04, N0-21); `native/include/mh4n/ipc.h`, `service.h` and `runtime.h`; `docs/native/golden.md`.
- **Files (allowlist):** `native/src/ipc_replay/**` (new: the replay logic), `native/tools/ipc_replay/**` (new: `main`), `native/tests/ipc_replay_test.cpp`, `config/native/ipc_time_dependent.txt` (new), `docs/native/ipc-replay.md` (new).
- **Spec:**
  - `mh4n_ipc_replay TRACE [--svc-trace FILE] [--service NAME]… [--continue] [--game DIR] [--user DIR] [--time-dependent FILE]…` reads a `--trace-ipc-full` trace and builds a process with the native kernel objects and the registered devices and services (`Runtime::Prepare` with the `devices` and `services` phases), but runs no guest code; deferred replies complete through the scheduler's `RunPending()`. `--service NAME` also selects the sessions a service hands out (`NAME/…`, such as `fs:USER/file#3`).
  - **Objects passed in requests** that came from SVCs (the event given to GSP's RegisterInterruptRelayQueue, say) are created from the SVC trace's creating calls, so the native service gets an object of the right kind.
  - For each request to the selected services (default: all registered), in trace order:
    - it writes the recorded words into a scratch thread's command buffer, and the recorded input buffers into a scratch guest memory at their recorded addresses;
    - it calls the service and waits for a deferred reply (draining posted work);
    - it compares the reply with the recorded one: header, result, normal words, and the CRCs of output buffers. Handles are compared through a map from reference handles to native ones, built as replies introduce them.
  - **Time-dependent commands:** `config/native/ipc_time_dependent.txt` (`<service> <header>  # reason`) starts empty, with a comment explaining the format; `--time-dependent` (repeatable) reads it and any other file given. Commands listed are compared by result only.
  - **Output** shows only service, header, result, descriptor index, size and CRC. Exit status 0 when nothing differs; without `--continue` it stops at the first difference per service.
- **Done when:**
  - ctest passes, with synthetic traces against a fake service: a match; a different result; a different output CRC; handle remapping across two replies; a deferred reply; an event created from the SVC trace; a time-dependent command from a second file;
  - (with the dump) replaying G1's `srv:` requests (`build/golden/G1/ipc.txt`, `svc.txt`) finds no differences.
- **Traps:** -
- **As built (N1-11), for N1-12, N1-14, N1-15 and N1-17 to N1-19** (the manual is `docs/native/ipc-replay.md`; the tool target is `mh4n_ipc_replay_tool` with `OUTPUT_NAME mh4n_ipc_replay`; the logic is the module `mh4n_ipc_replay`):
  - **Options:** `TRACE`, `--svc-trace`, `--service` (repeatable; `NAME` also selects `NAME/...`), `--continue`, `--game`, `--user`, `--time-dependent` (repeatable), `--reply-timeout MS` (default 30000, an addition of the worker) and `--help`. Exit status 0 (no difference), 1 (a difference) or 2 (bad input; also when nothing was replayed or `--service` names a service nobody registered). `config/native/ipc_time_dependent.txt` is read first when it exists relative to the current directory (run from the repository root); a bad line in any list is exit 2 with `file:line`; the format is that of `compare_ipc_traces.py --ignore`, and the file has no entry from N1-11 (no reply of `srv:` or `err:f` depends on time).
  - **Replay:** requests run in sequence order on one scratch thread (reply delay 0); deferred replies are waited for with `RunPending` in real time. Compared: the header, the result, the other normal words (by number only), output descriptor kind/index/size, buffer CRCs, null-ness and the native kind of handles. The output has only service, sequence number, session, header, result codes, descriptor index, size and CRC, and error messages never repeat text of the trace.
  - **Objects from SVCs:** the creating SVCs 0x13, 0x15, 0x17, 0x1A, 0x1E and 0x21 are made natively (a mutex unlocked, a memory block always from the BASE region); the SVC trace is lined up with the IPC trace per thread as `tracefmt.py` does, and CloseHandle lines close native handles.
  - **Limits:** a service session is found by name (the newest wins when a trace has several sessions of one service); a request with a handle that no reply or SVC call introduced is skipped with a reason; a GetServiceHandle wait for an unregistered service shows as "no reply within N ms". A service that a later WP adds to the registry is replayed by default: `--service` is how to limit a run.
  - **Checked here:** `conf_srv` from `port/tests` on the reference runner (`--trace-ipc-full`, `--trace-svc`) replays 17 `srv:` requests: 10 match and the 7 that differ are exactly the GetServiceHandle calls for `cfg:u` and `ptm:u`, which have no native service until N1-15. The native runner's own `conf_srv` trace stops at the first `cfg:u` request (it waits for the service), so it holds one request without a reply. The replay of G1's `srv:` requests is the pending (with the dump) item.
  - **Follow-up for `Runtime::Prepare` (N1-09):** it should set the game folder (for example from a `--game` option registered in the runner scope), so that a tool using `Prepare` gives the services a game folder; until then the tool builds a second `ServiceManager` (same registry, game folder from `--game`, SVC handlers pointed at it) when `--game` is given, and that block in `native/src/ipc_replay/tool.cpp` can go afterwards.
- **Out of scope:** the services themselves.

### N1-24 · Fallback interpreter: spike
- **Size / agent:** S · native-worker-high
- **Depends on:** N1-04, N1-09, N1-22 · **Needs:** none
- **Goal:** find out, before building it, whether the fallback interpreter (D13) can be generated from the recompiler's own instruction semantics.
- **Read first:** D13; [`../../RECOMPILER.md`](../../RECOMPILER.md); `tools/recomp/insn.py`, `arm.py`, `thumb.py` (the decoder, and the C each instruction becomes; registers, literals and short-vector lengths are baked into the strings, e.g. `arm.py` near lines 92–116 and 799–906); `tools/recomp/runtime/recomp.h` (the helpers that C uses); `tools/recomp/fuzz.py`; `tests/test_recomp_build.py` (how tests build C with clang).

- **Spec:**
  - **The approach:** `interp_gen.py` emits, for each instruction form the recompiler handles, a C function `ih_<form>(RCtx*, u32 insn)` whose body is what the recompiler emits for that form, with registers, immediates and the condition taken from `insn` at run time. ### N1-28 · Fallback interpreter

- **Depends on:** N1-24 · **Needs:** none
- **Goal:** (D13) code that wasn't recompiled runs in a minimal interpreter instead of stopping the game, and is logged for the next recompilation. Not on N1's critical path: the game runs without it as long as the code library covers everything.

### N1-25 · Deterministic mode and the shuffling scheduler
- **Size / agent:** M · native-worker-high
- **Depends on:** N1-06, N1-26, N0-17 · **Needs:** dump-check
- **Goal:** `--deterministic` makes runs repeatable (the same state hashes at every checkpoint), and `--seed N` moves preemption points reproducibly to flush out races.
- **Read first:** [`../ROADMAP.md`](../ROADMAP.md) §6 (*Determinism*); N0-17 (the `_native_det` library and its cycle charging); N1-06's interfaces; `golden.py`'s `--repeat` (N0-09); the quest-loading race in `docs/research/system-services.md`.
- **Files (allowlist):** `native/src/kernel/**` (the deterministic clock and preemption source, and the two options), `native/src/runtime/**` and `native/src/cpu/*` (loading the `_native_det` library with `--deterministic`), `native/src/services/fs/**` (synchronous mode), `native/src/services/gsp/**` and `native/src/services/hid/**` (updates at fixed times), `native/src/gpu_null/**`, `native/src/audio/**`, `native/tests/determinism_test.cpp`.
- **Spec:**
  - **Clock:** the cycles the `_native_det` code library charges, one tick per cycle at 268,111,856 Hz; the virtual cores take turns in fixed slices of N cycles, as Azahar's `RunLoop`.
  - **Host work at fixed virtual times:** fs requests complete synchronously, after Azahar's modelled delay; GPU interrupts after their modelled delays; VBlank every `FRAME_TICKS` (or the refresh rate's period); HID updates at their period; the DSP every 160 samples.
  - **`--seed N`:** each slice's length is drawn from a seeded generator within ½× to 1½× the default.
- **Done when:**
  - ctest passes: two runs of a synthetic multi-threaded program give identical traces; different seeds change the interleaving but not the results;
  - (with the dump) `golden.py check G1 --candidate-runner <native runner> --candidate-program build/native-game --candidate-code <the _native_det library> --candidate-args "--deterministic" --repeat 2` passes, and with `--seed` 1 to 5 the runs still reach the title.
- **Traps:** -
- **Out of scope:** making real-time runs repeatable.
