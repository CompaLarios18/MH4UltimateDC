# N0 · Foundations, oracles, baseline

Everything in N0 happens in the current, Azahar-based build (`port/`, `tools/`) or in docs. Nothing in it needs `native/` yet. The phase's goal and exit criteria are in [`../ROADMAP.md`](../ROADMAP.md#5-phases); the workflow is [`../AGENTS.md`](../AGENTS.md).

## Rules shared by the N0 packages

**Formats** (the recorders of N0-04 to N0-08 and N0-21, N0-22). Agree on these so the WPs don't diverge:
- **Text traces:**
  - one record per line, space-separated `key=value` fields after a fixed prefix;
  - numbers in hex are written `0x…`, lowercase, zero-padded to 8 digits for addresses and words. The exception is the existing SVC trace, which keeps its own fixed format: 8 uppercase hex digits without `0x`, as `TraceSvc` writes them; the fields N0-04 adds to it use the same style;
  - the first line is a header `# <tool> v1 <ISO date> game=<title id> cpu=<jit|recomp|interp|native> new3ds=<on|off>` (`cpu=` is the runner's `--cpu` value as given);
  - other lines starting with `#` are metadata (thread lines, notes). Every parser skips them.
- **Binary captures:**
  - magic (4 ASCII bytes), `u32` version, then records of `{u32 type, u32 frame, u64 ticks, u32 size, payload}`, all little-endian;
  - a sibling `<file>.json` manifest (tool, version, game, frames, record counts).
- **The frame number** in every record is the game's frame counter, the `u32` at `0x010571d4` (mirrored from `sLtRender+0x6b90`; see `docs/research/system-services.md`), read when the record is written.

**Reference runs are Old 3DS runs** (D10). Azahar's default is New 3DS mode (`Settings::values.is_new_3ds`, default `true`), which changes the cores, the FCRAM size and what cfg, ptm and APT answer. From N0-04 on, every reference recording runs `mh4u_runner --new-3ds off`.

**"G1" before N0-09 exists.** The golden sessions are defined in N0-09. Until then, a *(with the dump)* item that says "G1" means a power-on run with no input: `mh4u_runner <the staged CXI> --install <the staged update> --code <its code library> --new-3ds off --ms 60000` (plus the WP's own options), and "G1's title" means from game frame 1200 on, whatever is on screen then.

**The reference runner's files** (`port/src/runner.cpp`, `port/azahar/azahar.patch`, `port/README.md`, `port/src/arm_recomp.cpp`) are changed by many N0 WPs. Their dependencies chain them (N0-04 → N0-07 → N0-08 → N0-21 → N0-06 → N0-05 → N0-18 → N0-15 → N0-14), so only one is in flight at a time. Add your options, hooks and helpers next to the existing ones and keep them in your own functions, so the next WP's diff stays readable.

**Game data stays out of everything written for people:** everything recorded goes to `build/` (git-ignored), never into the repository, a PR or a report. Comparators print only service names, headers, result codes, descriptor indices, sizes, CRCs and counts, never buffer contents, so their output can be quoted.

**Checks only CI can run** are marked *(CI)*. The orchestrator runs them (AGENTS §7): it pushes the WP's branch, which runs `native.yml` (N0-03) and builds the reference runner when `port/`, `tools/` or `config/` changed; it then runs the items that need that build (downloading the artifact, the WP's *(with the dump)* items) itself. A worker reports them as `pending (ci)`. A worker can instead build the reference runner locally per `port/README.md` with `-DMH4U_PORT_DIR=<worktree>/port` (tens of minutes; one build-heavy WP at a time; run it in the background).

**Needs tags:** `dump` means the WP can't be done without the game files staged; `dump-check` means only the items marked *(with the dump)* need them. The rest of the tags are in [`../AGENTS.md`](../AGENTS.md#4-work-packages).

### N0-04 · Old 3DS runs, SVC results and normalised SVC traces
- **Size / agent:** M · native-worker-high
- **Depends on:** N0-03 · **Needs:** ci, dump-check
- **Goal:** the reference runner runs as an Old 3DS, its SVC trace records each call's real results and every thread created, and `compare_svc_traces.py` can match the traces of two runtimes, whose handles and thread ids differ.
- **Read first:**
  - `port/src/runner.cpp` (`TraceSvc` near line 569, option parsing, the `--help` text); `port/azahar/azahar.patch` (`SetSVCObserver`);
  - `tools/compare_svc_traces.py` and `tests/test_compare_svc_traces.py`; `tests/test_port.py` (`_svc_trace_by_thread`);
  - in Azahar: `src/common/settings.h` (`is_new_3ds`), `src/core/hle/kernel/svc.cpp` (CreateThread near line 1272; WaitSynchronization1 near line 810, whose real result is written when the thread wakes up), `src/core/hle/kernel/thread.cpp` (switching threads, waking them).
- **Files (allowlist):** `port/azahar/azahar.patch`, `port/src/runner.cpp`, `port/README.md`, `tools/native/tracefmt.py` (new), `tests/test_native_tracefmt.py` (new), `tools/compare_svc_traces.py`, `tests/test_compare_svc_traces.py`, `tests/test_port.py`.
- **Spec:**
  - **`--new-3ds on|off`** (default `off`): sets `Settings::values.is_new_3ds` before `system.Load`.
  - **SVC trace lines** keep their prefix and gain two fields at the end (after `t=`, so existing parsers ignore them), in the trace's own style (8 uppercase hex digits, no `0x`):
    `<thread> <svc> pc=<…> lr=<…> <r0> <r1> <r2> <r3> t=<ticks> in4=<r4>,<r5>,<r6> out=<r0>,<r1>,<r2>,<r3>`
    - `in4=` comes from the pre-call observer (timeouts and permissions live in r4–r6 for some calls);
    - `out=` holds the registers when the call **completes for that thread**: right after the handler for calls that return at once; for calls that block (waits, sleeps, a request whose reply is deferred), when the thread next runs. Hook the patch where Azahar switches to a thread that has a pending SVC, and write the line then. Within a thread the order stays the order of the calls. `out=-` marks a call that had not completed when the run ended.
  - **Thread lines:** for each CreateThread with a success result, `# thread <id> parent=<id> entry=<hex> arg=<hex> stack=<hex> prio=<n> core=<requested>/<resolved>` (ids and numbers in decimal, the rest in the trace's hex style). At the SVC r0 is the priority, r1 the entry, r2 the argument, r3 the stack top and r4 the processor id; the new thread's id comes from the handle in r1 after the call. The main thread gets one at start-up with `parent=0`. `<requested>` is r4 as a signed number (-2 means "default core").
  - **A header line** in the shared format.
  - **Parsers skip `#` lines:** `compare_svc_traces.py` and `tests/test_port.py`'s `_svc_trace_by_thread`.
  - **`tools/native/tracefmt.py`** (stdlib only): parses SVC traces and normalises them.
    - A thread becomes `<entry>#<k>`: the k-th thread created with that entry, in creation order, counting from 0. The main thread is `main`.
    - A handle becomes `<kind>#<k>` (k counts from 0 per kind), the kind from the SVC that created it (`event`, `mutex`, `semaphore`, `timer`, `arbiter`, `memblock`, `thread`, `port`); anything else (handles that came in IPC replies, until N0-21 names them) is `?`.
    - Time-dependent values (`t=`, and the outputs of SVC `0x28`) are dropped.
  - **`compare_svc_traces.py`:** `--normalize` (through `tracefmt`); `--outputs` also compares `out=` (r0 always; r1–r3 except handles, which are normalised, and SVC `0x28`; and except for a call that failed, with bit 31 of r0 set, or timed out, r0 = `09401BFE`, since Azahar's SVC wrapper writes the output registers whatever the result, so r1–r3 are leftovers then); `--in4` also compares `in4=`; traces in the old format still parse.
- **Done when:**
  - `python3 -m pytest tests/test_native_tracefmt.py tests/test_compare_svc_traces.py` passes, with synthetic traces covering: identical traces; a different result; a different interleaving across threads (must match); renumbered handles and thread ids (must match with `--normalize`); a blocking call whose line is written after other threads' calls; header and thread lines; the old format;
  - a unit test in `tests/test_port.py` shows `_svc_trace_by_thread` ignoring `#` lines (synthetic file; it runs without `MH4U_RUNNER`);
  - *(CI)* the runner job is green;
  - (with the dump) G1's first 30 seconds traced with `--cpu jit` and with `--cpu recomp` (both `--new-3ds off`) compare equal with `--normalize --outputs`.
- **Traps:** a plain post-call observer records provisional results for blocking calls (Azahar writes the real one at wake-up); that is why `out=` waits for the thread to run again. Azahar never reuses thread ids.
- **Out of scope:** the IPC trace (N0-21).

### N0-07 · Game-state trace and unmapped-access counter
- **Size / agent:** S · native-worker
- **Depends on:** N0-04 · **Needs:** ci, dump-check
- **Goal:**
  - `--state-trace FILE` writes the observable state at each game frame;
  - `--count-unmapped FILE` writes how often, and from where, the game touched unmapped memory;
  - `tools/native/state_diff.py` compares two state traces.
- **Read first:** `docs/research/system-services.md` (the addresses below); `port/src/runner.cpp` (`--dump`); in Azahar, `src/core/memory.cpp` (where unmapped reads and writes are logged).
- **Files (allowlist):** `config/native/observable.txt` (new), `port/src/runner.cpp`, `port/azahar/azahar.patch`, `port/README.md`, `tools/native/state_diff.py` (new), `tests/test_native_state_diff.py` (new).
- **Spec:**
  - **`observable.txt`:** one line per value, `<expr> <size> <name> <eq|ignore>`, where `<expr>` is an address or a pointer chain like `[[0x0104dea0]+0x30]`, and `ignore` values are recorded but not compared. Start with:
    - the scene byte `[[0x0104dea0]+0x30]` (1, eq);
    - the frame counter `0x010571d4` (4, eq);
    - the sMain delta `[[0x01057194]+0x5c]` (4, ignore: it follows the clock, which differs between runtimes);
    - the quest id `[[0x00edbe90]+0x9788+0x8c]` (2, eq);
    - the stage loader state `[[0x00fb7190]+0x42c]` (4, eq).

    A null pointer in a chain gives `-`.
  - **`--state-trace FILE [--observable FILE]`:** a line whenever the frame counter changes: `f=<n> t=<ticks> <name>=<value> …`, values in the shared hex style. `--observable` defaults to `config/native/observable.txt`.
  - **The unmapped counter:** count reads and writes Azahar's memory system reports as unmapped, by (address, size, read/write, guest LR). Write them sorted by count at exit.
  - **`state_diff.py reference candidate [--tolerance N] [--observable FILE] [--order-only]`:** aligns on scene changes, reports the first divergence, and exits 0 if every scene change happens within N frames (default 2) with equal `eq` values. `--order-only` compares only the sequence of scenes (the frames may differ: a run at another frame rate).
- **Done when:**
  - `python3 -m pytest tests/test_native_state_diff.py` passes (equal; shifted by 1 frame within tolerance; shifted by 5 frames only with `--order-only`; a different scene order; a null chain; an `ignore` value that differs);
  - *(CI)* the runner job is green;
  - (with the dump) G1's state trace shows the scene byte changing, and the unmapped report exists.
- **Traps:**
  - Read guest memory without side effects: no slow-path writes.
  - The list will grow; only the orchestrator edits it after this WP.
- **As built (N0-07), for the writers of the same formats (N0-08, the native runtime):**
  - **State trace:** header `# statetrace v1 …`; one line per frame-counter change, `f=<decimal> t=<decimal ticks> <name>=0x<hex, 2 digits per byte of the value's size>` or `<name>=-` for a null chain. The names are `scene`, `frame_counter`, `smain_delta`, `quest_id` and `stage_loader_state`; `state_diff.py` needs `scene` and `frame_counter`. Numbers are decimal in `f=` and `t=` (like the SVC trace's `t=`), and `state_diff.py` reads either style.
  - **Expressions in `observable.txt`:** the outermost `[..]` reads `<size>` bytes at the address inside; inner `[..]` are `u32` reads; a null or unmapped pointer gives `-`; a bare `0x…` is an address read at `<size>`.
  - **`state_diff.py`** compares the `eq` values only at the aligned scene-change records, and skips `frame_counter` there (the tolerance covers it).
  - **Unmapped report:** header `# unmapped v1 …`, sorted by count; it covers scalar reads and writes (and the CAS path) and the unmapped pages of block reads and writes (`ZeroBlock` and `CopyBlock` are not hooked); the LR is r14 of the running core. `--observable` defaults to the relative path `config/native/observable.txt`, so run the runner from the repository root or pass it.
- **Out of scope:** choosing more variables.

### N0-21 · IPC trace and comparator
- **Size / agent:** M · native-worker-high
- **Depends on:** N0-08 · **Needs:** ci, dump-check
- **Goal:** `mh4u_runner --trace-ipc FILE` writes every IPC request with its reply as Azahar's own IPC recorder sees them, deferred replies included, and `compare_ipc_traces.py` compares two traces after normalisation.
- **Read first:**
  - in Azahar: `src/core/hle/kernel/ipc_debugger/recorder.h` and `recorder.cpp` (`RequestRecord`: session and port names, the request and reply command buffers, translated and untranslated; `SetEnabled`, `BindCallback`), and where the recorder is fed: `src/core/hle/kernel/svc.cpp` near line 674 (`RegisterRequest`), `src/core/hle/kernel/hle_ipc.cpp` near line 233 (`SetRequestInfo`) and line 311 (`SetReplyInfo`, which also covers deferred replies);
  - `src/core/hle/ipc.h` (header and descriptor encoding: handles, static buffers, mapped buffers, the calling PID, PXI);
  - `docs/research/system-services.md`; `tools/native/tracefmt.py` (N0-04).
- **Files (allowlist):** `port/src/runner.cpp`, `port/azahar/azahar.patch` (only if a hook is missing), `port/README.md`, `tools/native/tracefmt.py`, `tests/test_native_tracefmt.py`, `tools/compare_ipc_traces.py` (new), `tests/test_compare_ipc_traces.py` (new).
- **Spec:**
  - **Recording:** `system.Kernel().GetIPCRecorder().SetEnabled(true)` and a callback with `BindCallback`.
    - At a request's record, take the CRC-32 of every input buffer: static buffers' data, and mapped buffers the client lets the service read.
    - At its reply's record, take the CRC-32 of every output buffer: what the reply wrote into the client's static receive buffers, and writable mapped buffers after the reply.
  - **One line per request,** written when its reply is recorded:
    `<thread> seq=<n> session=<name> cmd=<header> in=<every request word> desc=<kind:index:size:crc,…> out=<every reply word> outdesc=<kind:index:size:crc,…> t=<ticks>`. Words are untranslated (as the client wrote and read them), in the shared hex style. `seq` numbers requests in the order they were sent.
  - **Session names:** the recorder's port and session names for service sessions (`fs:USER`, `gsp::Gpu`, …). Sessions that a reply hands out through its handle descriptors get `<service>/<kind>#<k>` (for example `fs:USER/file#3`), so a comparator or the replay harness can select them.
  - **`--trace-ipc-full`** (a flag used with `--trace-ipc`) adds the bytes of the input buffers as `data=<index>:<hex>`, for the replay harness (N1-11).
  - **`tracefmt.py`** also parses IPC traces and normalises their threads (as in N0-04) and handles (in words and descriptors, `<session or kind>#<k>`). Given an IPC trace with an SVC trace (`--ipc FILE`), it also names the SVC trace's handles that came in IPC replies, instead of `?`.
  - **`compare_ipc_traces.py REF CAND [--strict] [--ignore FILE]… [--prefix] [--context N]`:**
    - groups requests by normalised thread and compares each thread's sequence of `(session, cmd, result, descriptor sizes and CRCs)`; `--strict` also compares every word;
    - `--ignore FILE` (repeatable) drops the commands listed in FILE (`<service> <header>  # reason`, the format of `config/native/ipc_time_dependent.txt`) from both traces; `--prefix` accepts a candidate shorter than the reference;
    - prints the first difference per thread with N requests of context, showing only session, header, result, descriptor index, size and CRC; exits 0 when everything matches;
    - documents the trace format in its docstring.
- **Done when:**
  - `python3 -m pytest tests/test_native_tracefmt.py tests/test_compare_ipc_traces.py` passes, with synthetic traces covering: identical traces; a different result; a different interleaving (must match); renumbered handles (must match); a different output CRC (must not match); `--ignore` with two files; `--prefix`; a deferred reply written after later requests of other threads; an SVC-trace handle named from the IPC trace;
  - *(CI)* the runner job is green;
  - (with the dump) G1's first 30 seconds traced with `--cpu jit` and `--cpu recomp` compare equal.
- **Traps:** full traces carry file paths, save bytes and the player's name: `build/` only, and never paste lines from them.
- **Out of scope:** decoding commands into names (a later convenience).

### N0-22 · GPU capture format and `gcap.py`
- **Size / agent:** S · native-worker
- **Depends on:** - · **Needs:** none
- **Goal:** one precise definition of the `MGPU` capture format (D23) with a reader, a checker, a summariser and a writer, shared by the recorder (N0-05), the censuses (N0-13, N0-14) and the capture player (N2-02).
- **Read first:** the formats at the top of this file; in Azahar: `src/video_core/gpu.h` and `gpu.cpp` (the calls a capture records), `src/core/hle/service/gsp/gsp_gpu.h` (`Command`, `FrameBufferInfo`), `src/video_core/pica/pica_core.h` (the state the `INIT` record holds), `src/video_core/pica/regs_texturing.h` (the fog mode: register `0x0E0`, bits 0–2; 7 is gas).
- **Files (allowlist):** `tools/native/gcap.py` (new), `tests/test_native_gcap.py` (new), `docs/native/mgpu-format.md` (new).
- **Spec:**
  - **Records** (the common binary format, magic `MGPU`); `mgpu-format.md` gives each payload byte by byte:

    | Type | Name | Payload |
    |---|---|---|
    | 1 | `INIT` | `u32` block count, then blocks `{u32 kind, u32 size, bytes}`: the GPU and LCD register blocks; the PICA internal registers; the vertex and geometry shader setups (program, swizzle data, float, integer and boolean uniforms); default attributes; the lighting, fog and procedural-texture LUTs; the immediate-mode and geometry-pipeline state. `mgpu-format.md` numbers the kinds and gives each layout as Azahar holds it |
    | 2 | `MEM` | `u32` physical address, `u32` size, bytes (at the start: all of FCRAM and VRAM) |
    | 3 | `CPU_PAGES` | `u32` count, then `{u32 physical address, 4096 bytes}` each: pages that changed since the last diff, taken before each GX command, register write, swap and colour fill |
    | 4 | `GX` | the 8 words of a GX command as `GPU::Execute` gets it |
    | 5 | `PICA_REG` | `u32` count, then `{u16 register, u8 byte mask, u8 0, u32 value}` each: the internal register writes the command processor made, after a `GX` record |
    | 6 | `GPU_PAGES` | as `CPU_PAGES`: the pages the GPU changed while executing a command (the reference output) |
    | 7 | `MMIO` | `u32` address, `u32` value (`GPU::WriteReg`) |
    | 8 | `SWAP` | `u32` screen, then the 7 words of `FrameBufferInfo` |
    | 9 | `FILL` | the `u32` colour-fill word |
    | 10 | `IRQ` | `u32` interrupt id, `u64` delay in ns |
    | 11 | `FLUSH` | `u32` kind (1 FlushDataCache, 2 InvalidateDataCache, 3 StoreDataCache, 4 a CacheFlush region), `u32` virtual address, `u32` size |
    | 12 | `FRAME` | `u32` the game's frame counter |

  - **`gcap.py`** (stdlib only):
    - `read(path)` → an iterator of records; a writer API, used by tests and later tools;
    - `summary FILE`: counts per type, GX commands per kind, frames, the fog modes set by `PICA_REG` writes to `0x0E0`, and per interrupt id the count and the minimum, median and maximum `IRQ` delay in ns;
    - `check FILE`: structural validity (known types, sizes, frames non-decreasing, every command-list `GX` followed by its `PICA_REG` record); exits non-zero if broken;
    - `memory_at(records, index)`: the memory before record `index` (sparse pages, from `MEM`, `CPU_PAGES` and `GPU_PAGES`);
    - `registers_at(records, index)`: the PICA register file from `INIT` plus the `PICA_REG` writes before `index`, honouring byte masks.
- **Done when:** `python3 -m pytest tests/test_native_gcap.py` passes, with synthetic captures from the writer: a valid one; truncated; wrong magic; an unknown type; memory reconstruction across `MEM`, `CPU_PAGES` and `GPU_PAGES`; register replay with masks; the fog modes and the `IRQ` delay statistics in `summary`.
- **Traps:** keep the format versioned: a change bumps the version, and readers refuse versions they don't know.
- **Out of scope:** recording (N0-05).

### N0-05 · GPU capture recorder
- **Size / agent:** M · native-worker-high
- **Depends on:** N0-06, N0-22 · **Needs:** ci, dump-check
- **Goal:** `mh4u_runner --capture-gpu START:FRAMES:FILE` records everything that crosses Azahar's `VideoCore::GPU` interface for FRAMES frames from game frame START, in the `MGPU` format, with the memory the GPU can see and a reference image of each frame.
- **Read first:** `docs/native/mgpu-format.md` and `tools/native/gcap.py` (N0-22); in Azahar: `src/video_core/gpu.h` and `gpu.cpp`, `src/video_core/pica/pica_core.cpp` (command-list processing and internal register writes), `src/core/memory.h` (FCRAM and VRAM, physical addresses); `port/src/runner.cpp` (`--shots`, the IPC recorder callback from N0-21).
- **Files (allowlist):** `port/src/runner.cpp`, `port/azahar/azahar.patch`, `port/README.md`.
- **Spec:**
  - **Why our own format:** Azahar still ships the CiTrace recorder (`src/core/tracer/`), but at the pinned commit nothing in the GPU code feeds it (no register writes or memory loads get recorded). Don't use it.
  - **Hooks** (observers in the patch, inactive unless capturing): `GPU::Execute`, `WriteReg`, `SetBufferSwap`, `SetColorFill`, the interrupt handler, and the PICA's internal register writes during command-list processing.
  - **`INIT`** from the GPU's and the PICA core's state at START; then `MEM` with all of FCRAM and VRAM.
  - **Ordering rules of the format** (`mgpu-format.md` §2, enforced by `gcap.py check`): one `INIT`, first, holding every block kind 1..11 exactly once in increasing order; each `FRAME` record's payload equals its header's frame; each command-list `GX` (command id 1) is followed immediately by a `PICA_REG` record (count 0 is allowed).
  - **Diffs:** keep a shadow copy of FCRAM and VRAM, and compare page by page (`memcmp`) before and after each GX command. Only while capturing.
  - **`FLUSH`** from the IPC recorder callback (N0-21): `gsp::Gpu` FlushDataCache (`0x00080082`), InvalidateDataCache (`0x00090082`) and StoreDataCache (`0x001F0082`) requests, and the regions of CacheFlush GX commands.
  - **Reference images:** at each `FRAME`, the top and bottom screens as PPM (`FILE.frames/<n>_top.ppm`, `<n>_bottom.ppm`) from the **software renderer at 1x**, which is the reference.
  - **Manifest** `FILE.json`: game, version, the game frames covered, the renderer, record counts, sizes.
- **Done when:**
  - *(CI)* the runner job is green;
  - (with the dump) a 3-frame capture of G1's title passes `gcap.py check` and has at least 3 command-list submissions, `PICA_REG` records, 3 `FRAME` records and 6 PPMs. Report its size.
- **Traps:**
  - Captures hold textures, shaders and framebuffers: game data, `build/` only.
  - They are large (about 140 MB of memory to start with on an Old 3DS), so cap FRAMES at 30.
  - `--draw-window` must not skip drawing during a capture; keep Azahar's `disable_right_eye_render` off (its default), or display transfers get skipped.
  - Update the shadow copy after the post-command diff, or the GPU's writes show up again as CPU changes.
- **Out of scope:** replaying captures (N2-02).

### N0-17 · `RC_NATIVE` mode in the recompiler runtime
- **Size / agent:** M · native-worker-high
- **Depends on:** N0-03 · **Needs:** ci
- **Goal:** the code library can be built for the native runtime: flat memory, and either a cheap preemption check (release) or the existing cycle charging (deterministic builds).
- **Read first:** `tools/recomp/runtime/recomp.h` (`RC_PAGED`, the flat mode, `RC_TICK`, `RC_NO_BUDGET`, `RHost`, `RC_HOST_VERSION`); `tools/recomp/build.py`; `tools/recomp/runtime/rc_dll.c`; `tools/recomp/harness/harness.c` (the flat harness, linked without `rc_dll.c`); `tests/test_recomp_build.py`; [`../../RECOMPILER.md`](../../RECOMPILER.md).
- **Files (allowlist):** `tools/recomp/runtime/recomp.h`, `tools/recomp/runtime/rc_dll.c`, `tools/recomp/harness/harness.c`, `tools/recomp/build.py`, `tools/build_game.py` (pass-through flags), `tests/test_recomp_build.py`, `tests/test_build_game.py`, `docs/RECOMPILER.md` (the runtime contract), `port/src/arm_recomp.cpp` (its `RHost` initialiser and the build-mode check).
- **Spec:**
  - **`RC_NATIVE`** selects the flat memory mode (the existing non-`RC_PAGED` path). `RC_TICK(n)` becomes:
    `if (__builtin_expect(*rc_preempt_flag, 0)) { RC_FLUSH(); rc_budget(ctx); RC_RELOAD(); }`
  - **`RC_NATIVE` with `RC_NATIVE_DETERMINISTIC`** keeps flat memory and the existing cycle-charging `RC_TICK` (the budget in `ctx->budget`).
  - `rc_preempt_flag` is a `volatile u32 *`. In a code library, `rc_code_init` sets it from a new `RHost` field, `preempt_flag`; bump `RC_HOST_VERSION` to 5. The flat harness defines it and gets a setter for its tests.
  - `rc_dll.c` exports `const u32 rc_build_mode`: 0 for `RC_PAGED`, 1 for `RC_NATIVE`, 2 for `RC_NATIVE` with `RC_NATIVE_DETERMINISTIC`, so a host can refuse a library built for another runtime with a clear message. The Azahar backend (`ARM_Recomp::LoadCode`) refuses anything but 0.
  - **Hosts that pass no flag** get a pointer to a static zero. The paged build behaves exactly as before.
  - **Build switches:** `python3 -m recomp.build <dir> --code-library --native [--deterministic]` defines `RC_NATIVE` (and `RC_NATIVE_DETERMINISTIC`) instead of `RC_PAGED`. `build_game.py --native [--deterministic]` passes them through and names the library `…_native.*` or `…_native_det.*`.
  - **Documentation:** the contract section of `docs/RECOMPILER.md`.
- **Done when:**
  - `python3 -m pytest` passes, including new tests:
    - a synthetic program built with `--native` runs in the flat harness;
    - setting the flag makes `rc_budget` run once;
    - a `--native --deterministic` build calls `rc_budget` when the budget runs out, as the paged build does;
    - each build exports the right `rc_build_mode`;
    - an `RC_PAGED` build of the same program still passes the existing tests;
  - the C generator is untouched: `git diff --exit-code origin/native -- tools/recomp/emit.py tools/recomp/arm.py tools/recomp/thumb.py tools/recomp/insn.py tools/recomp/analysis.py` prints nothing;
  - *(CI)* the runner job is green (the Azahar backend compiles against the new header).
- **Traps:**
  - Don't change `emit.py`'s output.
  - The Azahar backend is built with the same header, so update its `RHost` initialiser.
  - `RC_NO_BUDGET` (no checks at all) is not for the native runtime: a spinning guest thread would never give way on D1's single host thread.
- **Out of scope:** the native host (N1-04).
