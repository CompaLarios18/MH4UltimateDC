# N3 · Playable end to end at 120 fps (opt-in alpha)

The native executable `mh4u-native` of N2b becomes something a tester can play: our own HLE DSP with sound through SDL3, real input (controllers, the keyboard and mouse with the mouse camera, the Circle Pad Pro on `ir:USER`), the app's software keyboard and the error messages, saves in Azahar's layout with import and export of real 3DS saves, LayeredFS and code mods on the native loader, a native setup in the launcher with the HD pack step preselected, every hook point exercised natively, the 60/120 fps audit, the real-3DS check of gas (N2o-01, moved here), packages that carry `mh4u-native` next to the Azahar build, and reports a tester can send. The phase ends when **G1–G4, G6 and G7 pass end to end natively, an opt-in alpha is in the Windows and Linux packages, and the testers' reports are triaged** ([`LATER.md`](LATER.md), ROADMAP §5). The workflow is [`../AGENTS.md`](../AGENTS.md); the rules for code in `native/` are at the top of [`N1.md`](N1.md), the shared rules at the top of [`N0.md`](N0.md), and the rules of [`N2b.md`](N2b.md) (rules 1 to 12) apply to every package here, with the rules below.

**Where things stand (2026-10-22), and what N3 is written against.** N1-21 (the first boot) is being done by the local session; N1-26, N1-25 and N1-23 follow it. Of N2a, the capture player, the GX engine, the PICA command processor, textures and the HD pre-processor are done, and N2-24, the Vulkan probe, is next; D4 and D5 are open. Nothing of N2b is built. So most packages below are written against contracts the N1, N2a and N2b specs promise, not against code:

## Rules for this phase

These add to the rules of `N0.md`, `N1.md` and `N2b.md`.
1. **New modules first, one switch per service.** A change to a module N1 owns (`native/src/{memory,loader,kernel,runtime,ipc,services,applets,input_script,gpu_null,audio,platform}/**`, `native/src/cpu/*`, `native/runner/**`) is fenced: those modules are the fix area of N2b-18 to N2b-21. So N3 writes each new behaviour as a **new module** with its own tests (`native/src/dsp_hle/`, `native/src/audio_out/`, `native/src/ir_device/`, `native/src/code_patch/`, `native/src/layeredfs/`), which can start as soon as N1-21 is merged (`audio_out` sooner: it touches no service), and switches the services over to them in **N3-11** (the DSP), **N3-12** (`ir:USER` and the applets) and **N3-29** (the loader and fs), which depend on N2b-21. The same holds for the app: `native/app/runtime/**`, `shell/**` and `window/**` are N2b's until N2b-23, so the app-side modules (`native/app/audio/`, `native/app/input/`, `native/app/report/`) are wired in by **N3-14** (sound and input) and then **N3-30** (the keyboard, notices and reports).
2. **Audio thresholds** (ROADMAP §6): decoding and interpolation bit-identical to Azahar's HLE; the final mix at SNR ≥ 60 dB. Bit-identity is checked on our own programs (N3-01 and N3-11: every line equal to Azahar's output) and against Azahar's own code compiled by a harness (N3-02, N3-03); the SNR on replays of the reference's MDSP captures (N3-04, proposed D75). Across timing models the DSP capture is still compared by D51's rule (status blocks after a constant shift); no audio number is ever loosened.
3. **Our own 3DS programs** for public CI (`port/tests/snd_*.c`, `port/tests/ir_cpp.c`): built and run as `tests/test_conformance.py` does, their expected output written by the reference runner (`--cpu jit --new-3ds off`, two identical runs) into `port/tests/expected/<group>/`. They are never added to `PROGRAMS` of `tests/test_conformance.py` (that file is the N1 packages'); each group has its own test file that imports the helpers of `test_conformance.py` without editing it. Their samples and inputs are generated by the programs: nothing of the game.
4. **Defaults the player sees** change only with a decision (N2b's rule 12): the alpha is opt-in, the runtime the launcher starts and how, the HD step, what reports hold, the save formats, the error notices, the file-reply latency, the frame rate. Each is a row below; a package whose *Done when* ends with one stays `review` with `waiting for D<n>` until it is `Decided`.
5. **Privacy and game data in reports:** a report never holds memory contents, screenshots, captures, saves, game files, game text or file paths of the game, nor any path, name, address or online setting that identifies the player (proposed D69). `tools/native/report_check.py` (N3-13) is the gate. **Nothing logs** the keyboard's text or hint or the Error applet's text, at any level (N3-12, N3-30).
6. **Maintainer procedures** follow N2b's rule 10, for `3ds` items too: numbered steps, every PowerShell step from `Set-Location C:\NoJales\mh4pcport\repo` (the checkout of *Setting up mh4u-native on the reference PC*, `docs/native/app.md`), with exact commands and paths (AGENTS §6), the expected result and about how long each step takes, what he sends (lines of notes and the files of timings the procedure names, never screenshots or files of the game), and what to do on failure (stop; send the step's number and the last 50 lines of the log the procedure names). Procedures with the alpha package use a portable user folder: D61's `user\` next to `mh4u.exe`; `mh4u-native.exe` sits in `native\`, so it is always given `--user` (the launcher passes it, N3-19), never left to find `native\user\`; nothing touches `%APPDATA%\Azahar`.
7. **First guesses.** Every number in this file that ROADMAP §6/§7 or a D-row does not fix is a first guess and is marked so: the audio latency target (40 ms), the drift bound (±0.5 %), the overflow mark (200 ms), the underrun fade (64 samples), the replay's judged share (80 %) and its 1-second windows (D75), the audit's tolerances (D70), the observables' rules (N3-21), "no underrun after the first 10 s", the notice's 8 s, the alpha's two-week window, the mods run of N3-29. The maintainer's runs (N3-14, N3-27) and N3-22's tables confirm them; a wrong one stops its package with a `needs-decision` table, and the worker never retunes it.
8. **Runner options:** each package documents the options it registers in its own document and **proposes** the rows of `docs/native/runner.md` in its report (the orchestrator adds them); no package here has `runner.md` in its allowlist.

### N3-01 · Our own DSP test programs
- **Size / agent:** M · native-worker-high
- **Depends on:** N0-26, N1-18 · **Needs:** none
- **Goal:** 3DS programs of our own that drive `dsp::DSP` as the SDK does, with synthetic samples in every format the HLE DSP decodes, and print per DSP frame the status of each source and a CRC of the final mix: Azahar's output, committed, is the public-CI oracle for "decoding and interpolation bit-identical" and for the mix (N3-11 holds the native runtime to it).
- **Read first:** `port/tests/conf_services.c`, `svc.h`, `build_svc_test.py`; `tests/test_conformance.py` (building, running, `--regenerate`); 3dbrew *DSP Services*; in Azahar: `src/core/hle/service/dsp/dsp_dsp.cpp`, `src/audio_core/hle/hle.cpp` (`PipeWrite`, `CurrentRegionIndex`, `GenerateCurrentFrame`: final samples written into the write region), `shared_memory.h`, `source.cpp`, `mixers.cpp`, `effects.cpp`, `filter.cpp`, `src/audio_core/codec.cpp`, `interpolate.cpp`; `native/src/audio/dsp_layout.h` (the offsets as N1-18 has them).
- **Files (allowlist):** `port/tests/dsp.h` (new), `port/tests/snd_pcm.c` (new), `port/tests/snd_adpcm.c` (new), `port/tests/snd_mix.c` (new), `port/tests/expected/snd/**` (new), `tests/test_native_snd.py` (new), `docs/native/snd-tests.md` (new).
- **Spec:**
  - **`port/tests/dsp.h`:** `dsp::DSP` from `srv:`; `LoadComponent` of a 0x400-byte zero component (Azahar's HLE does not run it, `hle.cpp` `LoadComponent`); `RegisterInterruptEvents` for the audio pipe's interrupt with an event; the audio pipe's initialise command written with `WriteProcessPipe` as the SDK does, the structure addresses read back with `ReadPipeIfPossible`, the two regions found with `ConvertProcessAddressFromDspDram`; sample buffers in the linear heap (`svcControlMemory` with the linear flag), their physical addresses from the linear offset; `FlushDataCache` of what the program wrote, and a read of the region the DSP wrote last (the region rule of `CurrentRegionIndex`).
  - **Determinism:** every configuration a program changes is written before the frame that reads it: changes go through queued buffers (which play in order) or are written into the region the DSP reads next, right after the program has seen the frame interrupt and checked the frame counter. A program prints nothing between a change and the frame whose status reports it (`sync_count`). If the DSP's frame counter skips a value the program prints `missed <k>` (a failure line).
  - **Samples:** generated by the program with integer arithmetic (a 16-bit LCG with a fixed seed, and a sine table built by an integer recurrence, no floating point), so neither the program nor its output holds anything of the game.
  - **Output:** `<prog>: start`; then for each captured frame `k` (counted from the first frame in which the first source reports enabled), per enabled source `f<k>: s<i> en=<0|1> pos=<n> buf=<id> last=<id> sync=<n>` and once `f<k>: mix crc=<8 hex digits> peak=<n>` (CRC-32 of the 160 × 2 `s16` of the final samples); last `<prog>: done`. At most 400 frames; each program under 300 lines.

### N3-04 · DSP capture replay (`mh4n_dsp_replay`)
- **Size / agent:** M · native-worker
- **Depends on:** N3-03, N0-09, N0-10 · **Needs:** dump-check, save
- **Goal:** the audio oracle on the game, independent of timing models: replay a reference MDSP capture through our DSP, frame by frame with the captured inputs, and compare the mix with the reference's (D75).
- **Read first:** `tools/native/capfmt.py` (the MDSP format, N0-06's *As built*: type 1 regions at frame start, type 2 output, type 3 sample data with its bytes only the first time an (address, size, CRC) key appears); `docs/native/comparators.md` §8; `native/src/dsp_hle/` (N3-02, N3-03); `docs/native/golden.md` (G1's `dsp-1240` capture, G3); D75.
- **Files (allowlist):** `native/src/dsp_replay/**` (new), `native/tools/dsp_replay/**` (new), `native/tests/dsp_replay_test.cpp` (new), `docs/native/dsp-replay.md` (new).
- **Spec:**
  - **`mh4n_dsp_replay CAPTURE.mdsp [--report FILE]`:** reads the capture (a reader of its own in the module). **Sample memory:** a table keyed by (address, size, CRC) filled from the type-3 records that carry bytes; at each frame, every type-3 record of that frame (with or without bytes) copies its key's bytes into a sparse physical image at its address, which is our DSP's `SampleMemory`. A DSP frame's type-2 and type-3 records are those between its type-1 record and the next type-1 record, in record order (a record's `frame` field is the game's frame counter, not the DSP's, `capfmt.py`). For each DSP frame: the captured type-1 regions are copied into a DSP memory image, `dsp_hle::Dsp` ticks once (its own state carried from frame to frame), its output is compared with the frame's type-2 record, and the status it wrote with the next frame's captured status blocks.
  - **Settling:** a capture starts in the middle of the audio, so only the sources enabled in the capture's first frame need settling: such a source is settled at its second dequeue since the replay began, after one full loop of a looping buffer, or when it stops (disabled, or no buffer left), counted on our DSP; judging starts at the first frame by which every one of them is settled, and the frames before are reported, not judged. A source first enabled later is judged from its enable frame. Fewer than 80 % of the capture's frames judged (first guess) is a FAIL with `not settled`: for G1's `dsp-1240`, 300 DSP frames, that leaves 60 frames for settling.
  - **Verdict (D75):** SNR = 10·log10(Σ ref² / Σ (ref − ours)²) over both channels, at least 60 dB over the judged stream and in every window: windows of 205 DSP frames (32,800 samples, about one second), tumbling from the first judged frame, a last window shorter than 103 frames joining the one before; a window whose reference RMS is below 1 is judged by its largest absolute difference, at most 1. Every source status block equal. **Every judged frame that is not bit-exact is listed** with its frame number and its largest difference; more than 0 of them ends the package `needs-decision` with the list unless D75 is decided otherwise. It prints `dsp-replay: <n> frames judged of <total>, <m> bit-exact, snr <dB>, worst window <dB> at <frame>, status <equal|first difference at frame k>, PASS|FAIL`; exit 0, 1, or 2 for an unreadable capture.

- **Done when:**

- **Traps:** a looping PCM16 buffer's type-3 record repeats every frame without its bytes once its key is known (N0-06's *As built*): copy the key's bytes again at that frame. The capture is game data: `build/` only; the report quotes frame counts and dB.
- **Out of scope:** comparing a native run's own capture with the reference's PCM (timing models differ; D51 compares their status).

### N3-05 · Audio output stream
- **Size / agent:** M · native-worker-high (two threads share its state)
- **Depends on:** N1-18 · **Needs:** none
- **Goal:** what sits between the DSP (on the scheduler thread) and an audio device (on its own thread), with no SDL: a ring buffer, the drift controller that keeps the device's clock and the game's apart without ever pacing the game (D63), the underrun and overflow rules, and a WAV sink for tests.
- **Read first:** `native/include/mh4n/host.h` (`AudioSink`, `AudioSinkFactory`); `docs/native/runner.md` (`--audio`); in Azahar: `src/audio_core/dsp_interface.cpp` (`OutputCallback`: the FIFO, holding the last frame, the volume curve) and `src/audio_core/time_stretch.cpp` (`Process`: the backlog target and the low-pass of the ratio); D63.
- **Files (allowlist):** `native/src/audio_out/**` (new), `native/tests/audio_out_test.cpp` (new), `docs/native/audio-out.md` (new).
- **Spec:**
  - **The rate:** the DSP makes 160 samples every 1,310,720 ticks, 32,728.498 Hz of game time (`kTicksPerSecond / 8192`); a constant `kDspRate` holds it exactly as a fraction.
  - **`AudioSinkFactory` `stream`:** a single-producer single-consumer ring of stereo `s16` frames, 8192 frames (about 250 ms). `Queue` (scheduler thread) copies and returns. **Overflow** (the fill would pass 200 ms, first guess): `Queue` never moves the consumer's read index; it adds the excess to an atomic drop count and counts an overflow, and `Pull`, at its next call, skips that many frames first and adds them to `dropped`. **A full ring** (no consumer, or one that stopped): `Queue` writes only what fits (8192 − (write − read) frames) and discards the rest, counting it in `dropped`. `std::size_t Pull(s16* out, std::size_t frames)` (one consumer thread) copies what there is and fills the rest by the underrun rule: from the last sample given, a linear fade to zero over 64 samples (first guess), then zeros; one underrun is counted per run of short pulls. `Fill()` and `Stats()` (`queued`, `underruns`, `overflows`, `dropped`) are lock-free reads. `audio_out::Find(Runtime&)` gives the stream to the app (N3-06); `audio_out::PublishFrame(u32 game_frame)` and `LastFrame()` carry the newest game frame for the audio log (a `Runtime::OnFrame` subscription in this module).
  - **`DriftController`** (pure): from the fill, the target and the time since the last call it returns the factor by which the consumer's resampling ratio is multiplied, as Azahar's time stretcher steers its tempo (the tweak over 50 ms of the distance to the target, the 0.712 s low-pass), bounded to [0.995, 1.005] (±0.5 %, first guess), with provenance from `time_stretch.cpp` (the formula only).
  - **Options** (`runner` scope): `--audio-latency MS` (the target fill, default 40, first guess; 10 to 200).
  - **`AudioSinkFactory` `wav`** with `--audio-file FILE`: every queued frame into a 16-bit stereo WAV at 32,728 Hz (the header's sizes written at the end of the run, `Runtime::OnFinish`).
  - **When the game clock stands still** (pause, `Hold`, a stall): nothing is queued, the stream underruns, the device plays the fade and silence; when the clock moves again the stream fills to the target before the controller steers. Nothing ever waits on the device.
  - `audio-out.md`: the stream, the controller, the numbers marked as first guesses, its options (rule 8), and how the SDL3 side uses them (N3-06 adds).
- **Done when:** `ctest --test-dir build/native --no-tests=error -R '^audio_out_test$' --output-on-failure` passes: a simulated producer at 32,728.498 Hz and a consumer pulling 480-frame blocks at 48,000 Hz with its clock 0.01 % fast, both on a manual clock over 10 simulated minutes, keep the fill within 25 % of the target after 5 s, no underrun and no overflow, the ratio within its bounds; a 2 s stop of the producer gives exactly one underrun, the fade then zeros, and recovery; an overflow is dropped by the consumer (drop count, `dropped`) and the fill returns to the target; `Pull` and `Queue` on two real threads for 10^6 frames, with overflows forced, lose and duplicate nothing apart from the counted drops; with no consumer at all (as with N3-06's device that fails to open, or `--audio stream` in the runner), 10 simulated minutes of `Queue` keep the ring full, count the discarded frames in `dropped` and never block; the WAV sink's file is read back with the right header and samples.
- **Traps:** `Queue` runs on the scheduler thread: no lock, no allocation and no wait in it (principle 6). The consumer is a device thread: no logging inside `Pull`; counters only.
- **Out of scope:** SDL3 (N3-06); the DSP itself.

### N3-23 · Capture trimmer (N2o-01, part 1)
- **Size / agent:** M · native-worker-high (runs native builds)
- **Depends on:** N2-20, N2-04, N0-22, N0-10 · **Needs:** dump-check, save
- **Goal:** cut an `MGPU` capture down to what one frame's commands read, relocated into a compact layout with a relocation table, so a 3DS homebrew can hold it (G1's 3-frame capture is 144 MB); the result is itself an `MGPU` that replays like the original.
- **Read first:** `docs/native/mgpu-format.md` (§4: the INIT block kinds 1 to 11) and `tools/native/gcap.py` (reader and writer); `native/src/gpu/pica/regs.h` (the register numbers N2-04 uses: colour and depth buffers, texture units and cube faces, the vertex attribute base, the index array, the command buffer address and jump registers); 3dbrew *GPU/Internal Registers* and *GPU/Commands*; `docs/native/capture-player.md` (`--dump-frames`, `--gpu native`, `cpu-gx`, `pica-only --check registers`); `docs/research/gas.md` (N2-20: the gas frames); `LATER.md` (the N2b planner's notes on N2o-01).
- **Files (allowlist):** `tools/native/capture_trim.py` (new), `tests/test_native_capture_trim.py` (new), `docs/native/capture-trim.md` (new).
- **Spec:**
  - **`capture_trim.py CAPTURE --frame N -o OUT.mgpu [--fcram-base A] [--vram-base B]`** (stdlib, `gcap.py` imported): walks frame N's records and the INIT record; decodes its command lists (headers, masks, consecutive writes, the jumps through the command buffer registers) and its GX commands; finds every range they read or write (command buffers; vertex arrays from the loaders' offsets, strides and the largest index read from the index array; textures from address, size and format per unit and face; colour and depth buffers from their registers; fill, transfer, copy and DMA ranges), including the address registers held in INIT's register file; keeps those pages of the MEM records (and the frame's CPU_PAGES and GPU_PAGES for them), packs runs of contiguous pages into one FCRAM block and one VRAM block (bases default 0x20000000 and 0x18000000), and rewrites every address field to the new place, in INIT too; INIT, the frame's GX, PICA_REG, SWAP, FILL, FLUSH, IRQ and FRAME records follow. It writes `OUT.reloc` beside it and prints the two blocks' sizes.
  - **`.reloc`** (defined in `capture-trim.md`): a header (magic `MRLC`, version 1, the two bases and sizes) and one entry per rewritten field: record index, the field's place (an INIT register, a GX parameter, a command-list word, a register write), the segment (FCRAM or VRAM), the offset in it. `capture_trim.py rebase IN --fcram-base A --vram-base B -o OUT` applies it (the homebrew does the same at run time).
  - **Conservative extents:** where a range cannot be bounded exactly (a vertex array without an index array), the tool keeps up to the next unrelated page and says so; a field it cannot classify stops it with an error naming the register (never a silent copy).
- **Done when:**
  - `MH4N_CAPTURE_PLAYER=build/native/bin/mh4n_capture_player python3 -m pytest -rs tests/test_native_capture_trim.py` passes with 0 skipped: synthetic captures written with `gcap.py`'s writer (an INIT holding a texture and a colour-buffer address, a fill, a display transfer, a command list with a jump, a texture and an indexed draw) trimmed and rebased: every address moved by its segment's offset, INIT's included, kept bytes equal, `rebase` of a trim equals a trim at the new bases; and the capture player with `--gpu cpu-gx --isolated --judge fill,transfer` and with `--gpu pica-only --check registers` passes on the original and the trimmed captures;

- **Traps:** an address can sit in a register written by a consecutive-write block among other registers: decode every write, not only single ones. The captures are game data: `build/` only.
- **Out of scope:** the homebrew (N3-24).
